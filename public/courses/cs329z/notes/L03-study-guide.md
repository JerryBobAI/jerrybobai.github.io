## 一句话概览

**RAG = 不让模型记住一切，而是需要时去找**：从动机（证据胜过口才）与原始 RAG 论文（DPR + 生成器端到端训练），到索引工程（chunking、Anthropic contextual retrieval、late chunking、RAPTOR、GraphRAG、HNSW）、检索器与评估（BM25、DPR、hybrid/RRF、ColBERT），最后到 **Agentic RAG**（Self-RAG / CRAG / Search-R1）与失败模式清单。

### [0:00–0:05] 课程项目导引：选题、评估与建议

- 项目主规则：选你真正有热情的题目。要能回答：agent 做什么任务？背后的研究问题是什么？需要什么数据/API/框架？**怎么评估**？

### [0:05–0:10] RAG 动机与设计原则

- 两个答案的对比：问「答疑时段什么时候人最少」，裸 LM 凭先验猜「周三下午通常人少」；给它答疑**排队日志**后，它读出周二 16:00 有 14 人、周四 9:00 只有 3 人 → 建议周四早上去。两个答案听起来都通顺，差别不在口才，在**证据**——第二个答案附数据、可自查。
- RAG 设计原则：不让模型记住一切，而是**需要时精确找到**。两个记忆点：①**动态**——事实变了更新索引而不是模型权重；②**可解释**——模型能指出信息来自哪份文档，人可以回去核查。
- 前身：开放域 QA 的「检索-阅读」两阶段——检索器把数百万 Wikipedia 文章缩到少数候选，阅读器从候选中抽答案（分工：广度收窄 + 深度细读）。早期用 TF-IDF 检索 + 在 SQuAD（Stanford Question Answering Dataset）上训练的神经阅读器；今天可直接用 zero-shot LLM 当阅读器。

### [0:10–0:18] 原始 RAG 论文：组件、训练与结果

- 管线：query x → query 编码器 → 与文档索引做 **MIPS**（最大内积搜索，非参数部分）→ top-K 文档 → 生成器 P_θ（参数部分）逐 token 写答案 → 对文档做**边缘化**。
- **端到端**训练：梯度从生成器回流到 query 编码器；唯一**冻结**的是文档索引——它太大，且同一索引被 QA、事实核查、Jeopardy 式出题等多个任务共享。
- 两个变体：**RAG-Sequence**（选定一个片段生成整段答案）vs **RAG-Token**（每个 token 重新评估片段权重）。检索器与生成器联合训练，最小化负对数似然。
- 检索器 = **DPR**（Dense Passage Retriever）：两个 BERT 编码器分别编码问题与片段，点积排序；片段向量可**离线**一次算好存进索引，查询时只编码问题再 MIPS。
- 生成器 = BART（任意 seq2seq 皆可）：问题+检索片段拼接进 encoder。**没有专门的检索架构**——片段就是上下文里的原文，这就是 RAG 能直接平移到现代 LLM 的原因（在 prompt 里塞检索结果即可）。
- 结果：Natural Questions / TriviaQA / WebQuestions / CuratedTREC 上显著超 DPR-only、BART 等基线；人工评估中 factuality 与 specificity 多数情况更好——RAG 的核心贡献是**更好的 justification**（给出处、内容真的干了活）。
- 演化三代：**naive**（索引→检索→生成）→ **advanced**（检索前：query 路由/改写/扩展；检索后：合并/重排/摘要/综合）→ **modular**（拆成 search、routing、rewriting、reranking、memory、synthesis 模块，自由组合出 fetch-then-read、iterative search-read 等模式）。
- Q&A 洞见：新方法除了效果也要看速度/内存/成本；关键分野是「能否离线预计算」——cross-attention 式把问题与文档放进同一矩阵的编码器无法预计算。RAG 没有被现代模型淘汰：私域数据场景（金融服务公司的内部数据库）模型无从知晓，**必须 RAG**；通用网页搜索从 GPT-4 起已内置。BERT 如今已是过时技术，后面讲现代编码器。

### [0:21–0:26] 索引的原料：嵌入与相似度

- 嵌入层级：**静态**词向量（word2vec/GloVe，CS224N 内容）→ **上下文**嵌入（BERT：「bank」在金融语境编码金融义）→ **片段级**（Sentence-BERT、DPR）→ **多模态**（CLIP 把文本与图片放进共享空间；可扩展到音频+图+文）→ **图结构**（node2vec、GNN，嵌入捕捉节点与连接信息）。
- 有了好嵌入还需相似度度量：**cosine 距离或点积**——朴素但非常好用。这一页的要点：RAG 设计原则可泛化到极多数据形态。

### [0:26–0:34] Chunking 与 Anthropic contextual retrieval

- 切分策略与权衡：

| 策略 | 做法 | 权衡 |
|---|---|---|
| 固定大小 | 每块 100–500 token | 太小缺上下文；太大一块平均了多个主题 |
| Overlap | 相邻块共享 10–20% token | 保住跨界语境与句子边界，代价是内容重复 |
| 语义切分 | 以句子/段落为单位 | 更符合结构，属架构选择 |
| 上下文增强 | 每块附元数据/摘要 | 索引更可查找 |
| LLM 动态切分 | 用 LLM 找自然断点 | 语义最自然 |

- 例子：课程网页「项目评审在第 6 周」（讲师顺带提醒：这句是错的，以网站为准）——固定切分 vs 带 overlap（信息重复）vs 按标题语义切分（整块完整）呈现出的索引形态完全不同。
- **Anthropic contextual retrieval**：问题——查「ACME Corp 2023 Q2 营收增长」，检索回来的片段却没有公司名、季度、年份。做法：对每个片段用 LLM 扫**全文**生成 50–100 token 语境放在片段前面，让「这块在说什么」显式化；然后**双索引**：embedding（语义一致）+ BM25（精确数字、术语），取两界之长。代价：每个片段每次都要付一次 LLM 调用，不便宜。
- 效果数字：检索失败率（top-20 里失败占比）embedding 从 **5.7% → 3.7%**，hybrid 进一步降到 **2.9%**。

### [0:34–0:37] Late chunking

- 朴素切分是「先切块、再逐块嵌入」，每块只看见自己；**late chunking** 反过来：先把**整篇文档**喂给 embedding 模型得到丰富向量，之后再切分——每块都带上文档级语义。
- 实测收益规律：**块越小时 late chunking 提升越大**（块本来就大时，全文信息早已装得下，增益有限）——实用视角的调参线索。

### [0:37–0:45] 层级与图：RAPTOR、GraphRAG

- 数据结构升级：序列 → 树 → 图。
- **RAPTOR**（转写 "PeaKtor"，Stanford 工作）：答案散布全文档时单个片段不够用——自底向上建树：块嵌入 → 合并摘要 → 摘要再嵌入 → ……直到树根。查询时**所有层级一起搜**：细节问题命中叶节点，高层语义问题命中上层摘要节点。Cinderella 例子：「故事中心主题是什么」vs「她如何迎来圆满结局」——DPR 的箭头只指向叶节点，RAPTOR 能命中承载高层信息的块。
- **GraphRAG**：答案跨文档（如「公众如何看待某话题」，可能要看约 10 份文档）时，索引阶段让 LLM 抽取实体与关系建知识图 → 社区检测聚类；查询时不搜片段，而是让**每个社区摘要分别作答**，再合并局部答案成全局答案。
- Q&A 洞见：为什么切分越来越复杂——早期切分太局部，树解决「需要多块综合」，图解决「需要跨文档综合」；但复杂切分有成本，**今天商业级大规模 QA 系统仍偏好简单快速的方法**，因为覆盖大多数问题。社区选择是设计决策：定义 relevance score（例：「这周末看什么比赛」就选体育/赛事相关簇），可合并多个簇的局部答案。抽取用 LLM **够用即可、不必最前沿**：做准确率 vs 成本/速度的 Pareto 分析，实践中常用小而高效的模型而非大型商业 API。
- 错误级联 Q&A：RAG 管线一旦检索出错，最终答案必然不好——这是 RAG 固有限制；**agentic RAG** 会加自反思/批评组件缓解，但实践中问题仍在。

### [0:45–0:49] 向量检索：ANN 与 HNSW

- Top-k 检索：精确搜索复杂度 O(n·d)，n 是百万级记录——太贵。**ANN**（近似最近邻）：牺牲一点召回换大幅提速。
- 三类方法：**IVF**（对索引聚类，只在邻近区域搜）；**量化**（压缩向量表示、降维 d）；**HNSW**（分层可导航小世界图，最常用）。
- HNSW 直觉：所有向量在第 0 层，越往上采样越稀疏；查询**自顶层向下贪心**逼近 query，上一层找不到就降一层，每层做最近邻搜索；跳数量级约 **O(log n)**。构建：逐个插入向量、随机掷其顶层（大多数节点只留在 0 层）、每层连最近邻 + 启发式跨簇链接，保证贪心遍历不被卡死。

### [0:49–1:00:00] 检索器：BM25 与 DPR（含评估指标）

- **BM25**：1990s 经典、至今最广泛使用、每篇检索论文的基线；TF-IDF 风格。
  - **IDF 直觉**：词出现在 <50% 文档 → 正分；>50% → 负分——我们要的是对查询**独占**的词。
  - **K1 与饱和**：K1 小（0.5）≈ 二元指示器（词在不在）；K1 大（5）更看重重复次数、之后饱和。一句话：**IDF 决定哪些词重要，饱和防止单词支配**。
  - 优点：无需训练、无向量，精确术语匹配极难被打败。
- **DPR**：离线过一遍片段编码器（BERT/RoBERTa）建向量索引；在线编码 query → 点积 → top-k。两套独立编码器，思考题：哪边贵？（一边离线、一边在线，成本结构不同。）
- 训练用**对比损失**：正例相对负例的 softmax 负对数。负例两个来源：batch 内负例 + **BM25 难负例**（词面匹配问题但不含答案）——正是难负例教会模型**超越字面匹配**。
- 指标家族：**Hit@K**（top-K 里有没有相关）；**Recall@K**（找回了多少相关片段，与 Hit 互补）；**NDCG@K**（DCG 按排名位置折减相关性，再用理想排序 IDCG 归一）；**MRR**（第一个相关结果倒数排名的均值）。
- 结果：训练后的 DPR 在 5 个数据集中 4 个胜过 BM25（single = 单数据集训练，multi = 多数据集联合训练）；**仅需 1000 条标注对**就显著超 BM25；且无预训练、只用 1000–2000 对问答就超过了 ORQA（Google 早期端到端训练的检索系统）——样本效率惊人。

### [1:00:00–1:08:00] Hybrid search 与编码器家族：RRF、bi/cross-encoder、ColBERT

- 各自的盲区：**BM25 搞不定语义改写**（paraphrase），**DPR 会漏精确匹配**（特定代码、产品编号）。方案：两边都跑，按排名列表合并——**RRF**（reciprocal rank fusion，转写 "mutual rank merging"）合并的是**位置而非原始分数**（两套分数不可比），无需调参、不限检索器数量。
- 编码器四象限（本讲重要一页）：

| 方案 | 做法 | 权衡 |
|---|---|---|
| A. Bi-encoder | query 与文档分别编码后内积 | 最快；丢失交互、非位置感知 |
| B. 大矩阵联合 | query×文档矩阵一起处理 | 交互更强、开销大 |
| C. Cross-encoder | 拼接过 transformer 全注意力 | 质量上限最高；每个查询都要重算、**无法离线预计算** |
| D. Late interaction（ColBERT） | 每 token 存向量、独立编码、评分时交互 | 居中；文档侧可离线 |

- **ColBERT 的 MaxSim**：对 query 的每个 token，在文档 token 向量里找最匹配的一个取分，再对 query 所有 token 求和；编码独立、交互推迟到评分时刻。效果显著超 BM25 及各基线。
- 选型维度总结：语料形态（社媒文本 vs 充满专有实体的金融文档差异巨大）、能否离线预计算、查询延迟、每种检索器各自的失败场景。

### [1:08:00–1:15:00] Agentic RAG：Self-RAG、CRAG、Search-R1

- 前面所有 RAG 都是管线：没有主动性——不能决定**是否检索、问什么、何时停**。把检索变成 agent 的动作，需要三个决策：①搜还是直接答（需要事实信息吗）②要搜的话发什么 query ③结果够好了吗、可以停了吗。
- 三系统对比：

| 系统 | 思路 | 关键机制 |
|---|---|---|
| Self-RAG | 训练**单个模型**「检索-批评-生成」 | 文本中插入特殊**反思 token**；按需发 search token；对每个检索片段**并行**生成答案并自评（相关吗？被支持吗？），排序留优；需批评标注数据训练 |
| CRAG | **不动生成器**，在检索器与生成器之间插一个轻量评估器 | 评估检索文档打置信分 → 决策树：正确→保留/细化/拆分；错误→丢弃、改写 query、转网络搜索；模糊→两者都做；像裁判，可插入任何 RAG 栈 |
| Search-R1 | 用 **RL 学会**整个「想-搜-读-再想」循环 | R1 式思考 + 搜索模块：策略输出搜索词 → 搜索引擎 → 结果作为 token 回上下文；奖励即最终答案对错（PPO/GRPO 式，后讲）；无需人工写流程 |

- Search-R1 真实轨迹示例：「这里谁最老？」——模型想、搜、读结果、再想、再搜，**共搜 3 次、每次改写 query**，没有人给它写计划。这正是 L1 的 **workflow vs agent** 之分：循环是学出来的。结果显著优于 R1、SFT-RAG、Search-O1。

### [1:15:00–1:17:00] RAG 何时会失败（安全预热）

- **检索侧**：没找到正确证据；离线索引/embedding 过时；检索到了不该看的内容。
- **阅读侧**：**lost in the middle**——长上下文里模型会分心、忽略中部信息；外部证据互相矛盾时怎么办。
- **管线级联**：早期一个错误污染后续所有决策（呼应 GraphRAG 节的 Q&A）。
- **检索文档中的 prompt injection**：攻击者只要污染语料就能攻击整条管线——后续安全讲次展开。

## 自测题（先遮住右侧再答）

1. RAG 设计原则的两个记忆点？用课堂例子说明 RAG 改变了什么。
   > ①动态：事实变化时更新索引而非模型权重；②可解释：能给引用供人核查。课堂例子：裸 LM 凭先验猜「周三下午人少」，给排队日志后读出「周二 16:00 有 14 人、周四 9:00 只有 3 人」→ 建议周四早上——差别在证据而非口才。
2. 原始 RAG 论文里什么被冻结、什么被训练？RAG-Sequence 与 RAG-Token 的区别？
   > 文档索引冻结（巨大且多任务共享）；query 编码器与生成器端到端联合训练（最小化 NLL，梯度经生成器流回 query 编码器）。RAG-Sequence 用一个片段生成整段答案；RAG-Token 对每个 token 重新评估片段。
3. Anthropic contextual retrieval 做什么？为什么双索引？数字是多少、代价是什么？
   > 对每个片段用 LLM 扫全文生成 50–100 token 语境放在块前。embedding 管语义一致性、BM25 管精确数字/术语，各取所长。检索失败率（top-20）从 5.7% 降到 3.7%，hybrid 到 2.9%；代价是每个片段每次都要一次 LLM 调用。
4. Late chunking 为什么在小块时收益最大？
   > 先整文嵌入再切块，每块携带文档级语义；块很大时本身已含足够上下文、增益有限，块小时全文级信息的补充最显著。
5. HNSW 的查询流程与复杂度？IVF 和量化各做什么？
   > 分层图：0 层全量、上层稀疏；查询自顶层向下贪心逼近、找不到就降层做最近邻，跳数约 O(log n)。IVF 对索引聚类后只在邻近区域搜；量化压缩向量表示、降低维度。
6. BM25 的 IDF 和 K1 分别编码什么直觉？DPR 的难负例为什么关键？
   > IDF：词出现在 <50% 文档得正分、>50% 得负分——奖励对查询独占的词；K1 控制 TF 饱和速度：小 K1≈二元存在性、大 K1 更看重重复。BM25 难负例（词面匹配但不含答案）逼 DPR 学会超越字面匹配。
7. Self-RAG、CRAG、Search-R1 一句话区分？
   > Self-RAG 训练单个模型带反思 token，按需检索、并行生成并自评排序；CRAG 不动生成器，在检索器与生成器之间放轻量评估器按置信度决定保留/改写查询/转网络搜索；Search-R1 用 RL（PPO/GRPO + 搜索模块）学出整个「想-搜-读-再想」循环，奖励是最终答案对错。
