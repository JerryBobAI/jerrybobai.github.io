## 一句话概览

本讲围绕「**规划与多步推理**」精读三篇论文：**LATS** 把 MCTS 带进 LLM，让推理-行动-规划统一在树搜索里；**SPRINT** 用 LLM 自标注的合成数据教推理模型把独立步骤并行执行；**SWiRL** 用合成多步数据 + 多步 RL 教模型带工具逐步推理——共同主线：多步任务的错误会级联，要靠树搜索、并行化与过程级监督把测试时算力真正兑换成正确率。

## 分节要点（带时间锚点）

### [0:00–0:05] LATS：统一推理、行动与规划

- 本讲第一篇 **LATS**（Language Agent Tree Search,去年 ICML），标题即主张：把 reasoning、acting、planning 统一进语言模型。
- 目标应用是「既要推理、又要行动、还要搜索」的多步任务：推理定计划与预算，行动去搜集信息（浏览网页、向 Reddit/旅游博客发查询），搜索则根据反馈修正计划、考虑替代目的地——例子是规划一次夏威夷旅行。
- 要解决的挑战：从「LLM 生成一个计划然后执行」走向**多样化探索**不同计划与路径——模型至今仍不擅长生成多样的解、也不擅长做多步优化逼近正确答案。
- 做法：把 RL 与多步规划的成熟技术（含 multi-step Monte Carlo search / **MCTS**）引入 LLM 推理路径；每个动作打分、按分扩展搜索树（如高分动作「问朋友 A 和 B」被展开），环境反馈再用于修正后续计划与搜索。
- 带有 multi-action sampling 的味道：若干动作可**并行执行**；在「沿最优状态继续」与「探索-利用混合」之间权衡——这正是 MCTS 登场之处。

### [0:05–0:15] LATS 六阶段流程走读：迷宫示例与打分机制

- 与 **Math Shepherd**（此前讲过）的分野：那篇用 verifier 在测试时按**推理步骤**打分引导搜索；LATS 改为按 **action 的 outcome** 打分，外加模型对轨迹的 reflection 与环境观察。
- 相对 **ReAct** 的增强：加了记忆/反思、与环境的交互反馈进未来搜索，以及更多显式**规划**；直觉拼图 = CoT（推理分解成步）+ 树扩展（动作生成形成搜索树）+ ReAct（动作反馈回灌）。
- 六个阶段：**Selection、Expansion、Evaluation、Simulation、Backpropagation、Reflection**。
- 迷宫示例（prompt:走到出口；初始观察：昏暗房间、左右两扇门）：Selection 按 UCT 选节点；Expansion 采样 3 个动作——开左门、开右门、检查房间找线索；每个动作在环境中执行，观察（如「挂满画的黑暗走廊」）追加进上下文。
- Evaluation：状态分 = **LM score**（LLM-as-judge 对「这个状态多有希望」打 0-1 分）+ **self-consistency score**（假设采样约 50 次动作、按被抽到的频率打分，如 state A 占 75% 更高），两者相加。
- Simulation：贪心地把最高分状态（如 SA）一路扩展，直到终态（成功/失败）或扩展预算耗尽；示例中恰好走到明确标记的出口门。
- **UCT**（upper confidence bounds applied to trees,承自 MCTS）用于选节点：V(s) + 超参 × 探索项，探索项用父节点访问数 n_p 与当前节点访问数 n_s 之比——相对父节点访问越少越该被访问，访问多了分数自然走低；只算当前最高分会错过「当下低值、终局高值」的分支。课堂确认：承自 bandit 的 UCB 思想，**没有最优性证明**，是探索-利用的启发式平衡。
- **Backpropagation**：轨迹的 return 沿步骤回传，新价值 =（旧价值 ×（访问数−1）+ return）/ 总访问数；**Reflection**：轨迹成败后模型追加一段自我复盘（什么导致了成败），讲者称对整体质量提升帮助很大。

### [0:15–0:20] LATS 实验结果与两大局限

- **HotpotQA**：每题按设计需从至少 2 个不同 Wikipedia 页面检索（天生 multi-step）；采样轨迹数越多性能显著提升，reflection 也带来可观增益——把测试时算力有效兑换成更好的多步推理解。
- **WebShop**：实用购物数据集（例：「小型便携、已完全组装、指定颜色/做工与价格的桌子」）；**完全不做微调**、纯测试时方法即可接近人类专家水平。
- 总结优点：统一推理+行动+规划、把 MCTS 带进 LLM 世界、多域强结果；测试时方法 + 模块化 ⇒ 可移植、相对容易搭建。
- 局限一：**成本**——树扩展与反向传播开销巨大，论文没有做成本-收益分析。
- 局限二：未处理**不可逆动作**——模型执行交易、付费服务等后果性动作时无法试错回滚，该方法难直接适配这类场景。

### [0:20–0:25] 课堂讨论与 SPRINT 动机：长推理里的独立步骤

- Q&A：UCT 之外还有整片 multi-arm bandit 文献，其他探索-利用算法都可接入——讲者认为 LATS 的主要贡献是提供了这样一个**平台**，让后人能把各种优化方法搬进来。
- Q&A（轨迹中的重复动作）：同一动作在给定父节点下重复出现就增加计数，UCT 公式会自然吸收；整个方法建的是**树**而非全连通图，这是方法论假设。
- **SPRINT**（2025 新论文，当时尚未在会议正式报告）：动机是推理模型（o1、Gemini think、Gemini 2.5 Pro 等前沿模型）**问题越难想得越久**，更长思考对应更高准确率。
- 证据：DeepSeek R1 训练过程中数学题越解越好，同时**平均回答长度也在持续上涨**——思考长度与准确率呈正相关。
- 但细看推理轨迹：许多步骤**相互独立**——尝试替代方案、把任务分解成可并行的子任务、验证之前的步骤；没必要让所有步骤串行生成，应该利用这种并行性。

### [0:25–0:35] SPRINT：LLM 自标注合成数据与并行执行机制

- 核心思路：让模型自己识别并行化机会并付诸行动；这里再次出现贯穿全课的套路——**用 LLM 自己制造微调数据**。
- 管线：DeepSeek R1 对问题生成推理轨迹 → **GPT-4o** 逐步标注（步骤 1..k），标出每步里哪段是 **plan**、哪些是 **execution**（一个 plan 可对应多个 execution）。
- 再用模型标注步骤间依赖、构建 **DAG**（如步骤 4 与 2 互不依赖、都依赖步骤 1），然后 **packing**：步骤 1 先行，2、3 完全并行。
- 用带标签的轨迹做**监督微调**：模型学会在推理时自己输出 plan/execution 标签；本质仍是 next-token prediction，标签只是让输出带上可执行的结构（Q&A 确认）。
- 推理时：模型先连续生成 plan 1 与 plan 2，两个计划的执行**同时**开跑（执行可以是调用计算器/Python 等工具），同步结果回填上下文，再进入下一组计划——**规划-执行交错**推进，Sequential 时间线被压缩。
- Q&A（计划中途要改怎么办）：模型始终看得到全部上下文，仍可回退修改；训练目标只是让它**每一步都最大化并行思考**，独立的 plan 2 不必等 plan 1 执行完才生成。

### [0:35–0:45] SPRINT 训练配方、精度与 OOD 泛化

- 配方：为数学数据集生成 **6K 条思考轨迹**，保留**并行化程度更高**的子集，对 **DeepSeek-R1-Distill-7B** 做监督微调。
- 意外收获：除省 token 外**精度也涨了**——比 R1-Distill-7B 基线高 **3.5%**，同时顺序 token 数比 **32B** 模型还少；模型似乎受益于这种更结构化的思考方式。
- **OOD 泛化**：只在数学上训练，没训过的 **Countdown** 与 **GPQA Diamond** 上并行机会与准确率同样提升——「学会并行思考」本身对模型有益，并行省 token 只是副作用。
- 规律：越难的问题需要越多轮迭代的规划-执行；**前期探索更多并行**，后期收敛到更少计划、深挖单条执行。
- Q&A（并行分支结论矛盾怎么办）：所有结果都回填进上下文，模型应在生成最终答案前自行解决矛盾；这些并行计划是同一问题的**不同步骤**，不是对同一问题的不同解法。
- Q&A（负载均衡）：可能出现 straggler（步骤 4 远慢于步骤 2），总时长受限于最慢分支；执行太简单会被合并进 plan 形成更大的并行块——跨阶段优化仍是开放问题。
- 树宽 task-dependent：数学的可并行比例低于 GPQA；能榨出多少并行度取决于任务本身。

### [0:45–0:50] 40% 顺序 token 削减、Sonnet 4.5 佐证与未来工作

- 与 **RFT**(rejection fine-tuning)基线相比：精度相当的前提下，数学数据集上把**顺序 token 减少约 40%**。
- 省得多不多取决于问题难度：**越难、思考 token 越多的问题节省越大**；简单问题思考本来就短，少了并行机会，SPRINT 甚至可能比基线更差。
- 佐证趋势：讲者提到 **Sonnet 4.5** 系统卡的 prompt 竟鼓励模型**至少用 100 次工具**；前沿模型解题已远超 8-10k token——多步推理的推理成本与延迟正成为大负担，这正是 SPRINT 要压缩的东西。
- Q&A（推理机制澄清）：计划仍是**顺序生成**的，只是一旦输出多个独立计划，它们的执行就并行启动、结果回填后再生成下一组；训练数据里「每步 = 一个 plan + 一组 executions」与此对应。
- 未来工作：换成 **RL / GRPO** 训练可能收益更大、泛化更好；工具重叠调度与**真实 wall-clock 加速**的落地也留待后续实现。

### [0:50–1:00:00] SWiRL：动机、多步合成数据与两种过滤

- **SWiRL**（下周在蒙特利尔 **COLM** 报告）：延续「合成多步数据 + 训练」路线，教模型把多步推理与工具使用一起做好。
- 动机：多跳问答（搜索引擎）、数学、软件工程、旅行规划、数据分析都需要**多步推理 + 工具**；推理和工具调用一旦展开成多步，**错误与复杂度会随步骤级联放大**。
- 两个训练侧难点：真调工具很难——工具会失败、慢、有 bug，本来就耗时的训练更被拖慢；且 RLHF/RLAIF/执行反馈等既有微调大多针对**单步任务**（只按最终答案给奖励、再回传），缺少对过程的掌控。
- 设计目标：会解复杂多步问题、知道**何时**调工具、**写对**工具查询、保持步间准确率、学会**从错误恢复**、知道何时停止调工具并输出最终答案；训练全程**回避真实工具调用**；并能泛化到新工具与新任务。
- 数据生成：让模型**一次走一步**，每步自由选择推理(CoT)、调工具或提出最终答案；**迭代提示**——原 prompt + 上一步动作 + 环境结果一起喂回，再要下一个动作，不同问题的步数从 1 到 3 或 5 不等。
- 打标：**LLM-as-judge** 在「先前上下文 + 当前动作」下给每步估计 reward；打分可**离线并行**跑大量问题。
- 两种过滤口径：**process filter**（judge 判定每一步都好才保留）vs **outcome filter**（只要最终答案正确就保留，不管逐步标签）——两者如何取舍是后面实验的关键变量。

### [1:00:00–1:05:00] SWiRL 多步 RL 机制：不执行工具的过程奖励

- RL 示例（「比较两个人谁更年长」）：动作 1 搜第一人年龄 → judge 给该步奖励 → 展示预收集的环境响应 → 动作 2 搜第二人年龄 → 奖励 → 最后模型输出 answer 标签的最终答案 → 再得奖励。
- **关键机制：RL 训练中不真执行工具**——整条轨迹的工具调用全部在离线数据期预收集；训练时模型基于 prompt+已有步骤提出下一个动作后，只按**这一个动作**从 judge 收集奖励用于 RL 优化。
- Q&A（judge 看不到工具输出怎么打分）：judge 评的是**模型为工具生成的查询质量**，不是工具输出——判断「这是否是给搜索引擎的合理问题」不需要知道答案；这是**过程奖励**，工具调用本身已捕获在先前上下文里。
- judge **不做任何训练**，纯 prompt 即可。
- 目标函数：优化**单步动作在全部先前上下文**（已收集的状态与动作序列）下的期望奖励，对 action 1..K 逐步进行——多步 RL 而非只在终点给奖励。
- 推理流程：prompt 声明可用工具（如计算器）与标签格式（数学查询用特定标签包住、够了就输出 answer 标签）；每步「输入+上一步结果」迭代提示，模型决定继续调工具还是收尾作答。

### [1:05:00–1:10:00] SWiRL 结果：过程过滤胜出、跨任务泛化与总结

- 实验设置：用一个 Gemini 系模型（字幕转写为「GMO 227B」,具体型号存疑）生成多步合成数据；题目来自 **HotpotQA** 与 **GSM8K**，约 **50k 条轨迹**；过滤方式含 process / outcome / 双重 / random。
- 反直觉发现：**只用 process filter 的数据训练效果最好**，胜过 outcome 正确或双重过滤——只训「结果本来就对」的轨迹，教不会模型解它测试时解不了的新题；而「过程好但结果错」的轨迹反而教会它换一种方式思考。
- **跨任务跨工具泛化**（讲者最看重）：GSM8K（计算器）上做 RL → HotpotQA（搜索工具）测试精度 **65 → 75.1**；HotpotQA（搜索）训练的域内提升是 **65 → 73**；反向同样成立（HotpotQA+搜索 → GSM8K+Python）——模型学到的是**分步思考与调用工具**本身，而非某个具体工具。
- **Scaling**：训练数据从 100 → 10,000 条，在完全没训过的 GSM8K 上推理持续变好——在容易造数据的环境里教工具与多步思考，可迁移到全新工具与领域，放大合成数据可能是很强的方法论。
- 机理解释：RL 后模型**每步过程正确率**(average process reward per step)在域内(HotpotQA)与 OOD(GSM8K)都提升——模型逐步想得更对，而不只是答案碰巧对。
- **RL vs SFT**：多步 RL 明显好于 SFT；SFT 需要 process+outcome 双过滤才好用（本质是模仿学习，错轨迹有害），RL 则给模型基于先前步骤重新行动的机会、按新动作给奖励，因此能跳出错误轨迹。
- 总结：SWiRL 跨数据集与工具泛化、能迁移到不同任务、从 process 过滤数据学得更好、更多合成数据持续涨分（域内外皆然），根源是**过程正确率**的普遍改善——多步推理与规划是非常活跃、仍在快速前进的领域。

## 自测题（先遮住右侧再答）
1. LATS 的六个阶段依次是什么？
   > Selection → Expansion → Evaluation → Simulation → Backpropagation → Reflection；迷宫示例中每执行一个动作就把环境观察追加进上下文。
2. LATS 给状态打分的两个组成部分各是什么？怎么计算？
   > LM score：LLM-as-judge 对「该状态有多大希望」打 0-1 分；self-consistency score：动作在约 50 次采样中被抽到的频率（如 state A 占 75%）；两者相加为该状态价值。
3. UCT 公式如何平衡探索与利用？各符号含义是什么？
   > V(s)+c·√(ln n_p/n_s)：V(s) 是利用项；n_p=父节点被访问次数、n_s=当前节点被访问次数，相对父节点访问越少分越高、越优先扩展；承自 MCTS/bandit 的 UCB，无最优性证明。
4. LATS 相对 Math Shepherd 与 ReAct 各改了什么？
   > Math Shepherd 用 verifier 按**推理步骤**打分，LATS 改为按 **action 的 outcome** 打分并加反思与环境观察；ReAct 是想-动循环，LATS 再加记忆/反思、反馈回灌未来搜索与显式树规划。
5. 讲者总结 LATS 的哪两大局限？
   > 成本：树扩展+反向传播开销巨大且论文未做成本收益分析；不可逆动作：真实交易/付费等场景无法试错回滚，方法难直接适配。
6. SPRINT 的核心观察、数据管线与训练配置是什么？
   > 观察：长推理中许多步骤相互独立可并行；管线：DeepSeek R1 生成轨迹 → GPT-4o 标注步骤/plan/execution → 建 DAG → packing；训练：保留高并行化的 6K 数学轨迹，SFT DeepSeek-R1-Distill-7B。
7. SPRINT 有哪些关键数字结果？
   > R1-Distill-7B 精度 +3.5%，顺序 token 比 32B 模型更省；对比 RFT 基线在相当精度下顺序 token 约减 40%；数学训练可 OOD 提升 Countdown 与 GPQA Diamond；难问题省得多、简单问题可能反而更差。
8. SWiRL 为什么训练时不真执行工具？judge 凭什么给过程奖励？
   > 工具会失败/慢/有 bug 会拖慢训练，工具调用全部在离线数据期预收集；judge 只评模型为工具生成的查询质量（如「这是否是给搜索引擎的合理问题」），无需看工具输出，按单步动作在给定上下文下的期望奖励做 RL。
