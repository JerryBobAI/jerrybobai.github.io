## 一句话概览

RLHF 收尾（过优化、校准退化）后进入正题：可验证奖励(verifiable rewards)强化学习如何催生推理模型——从策略梯度出发经 PPO 到 GRPO（用组内 z-score 基线替换价值模型），再用 Dr. GRPO 的两个修正揭示实现细节如何塑造模型行为；最后以 DeepSeek R1、Kimi K1.5、Qwen 3 三个案例拼出推理模型训练配方的全貌。

## 分节要点（带时间锚点）

### 一、RLHF 收尾：变体、教训与本讲转向([0:00])

- DPO 快速回顾：成对偏好数据下，用非参数假设（策略类=全体函数）把 reward 改写成策略之比，代入 Bradley-Terry 目标——RL 目标变成一种换了参数化的监督学习；梯度形式=按「隐含 reward 估错的程度」加权，升好例、降坏例。RL 算法大都能归结为「升好降坏」，微妙之处全在如何判定好坏、加多少权([0:00])
- DPO 曾一度主导开源模型 post-training（比 PPO 容易跑通），随后涌现海量「*PO」变体论文；讲者只挑两个近期真被极限使用的：SimPO（更新幅度按回答长度归一化 + 干脆去掉参考策略）与 length-normalized DPO（只做长度归一化）——AI2 在 Tulu 3 里对两者都做了大量实验([0:00])
- 重要经验：RL 的结论高度依赖具体设定（环境、基模型、偏好数据）——AI2 早先发现 PPO 因 on-policy 胜过 DPO，到 Tulu 3 把 SFT 做得更好后，两者增益全被吃掉、只剩 length-normalized DPO 略胜。单篇论文的结论别当普遍规律，本讲后面 PPO/GRPO 的结果同理([0:05])
- 过优化(overoptimization)：本质是给过拟合起了个花哨名字——proxy reward 一路上涨，但拟合的 reward model 与真实人类偏好迟早分岔，真实胜率先升后平台甚至回落；学生的研究：人类偏好与加噪 AI 反馈都出现明显过优化，干净无噪的 AI 反馈则没有。做 post-training 就该预期看到这种曲线([0:05])
- 附带提醒：RL 之后不再是概率建模——是策略，没有底层分布；RLHF 模型普遍校准(calibration)变差、温度 1 下过度自信（Anthropic、GPT-4 发布报告等多个来源）。校准不在奖励里，算「按设计」，但别再把这类模型当校准的概率模型用([0:05])
- 转向：人类反馈难优化、难规模化、易被 hack——借鉴 AlphaGo/AlphaFold 的启示，寻找「知道真实奖励、且能快速大规模评估」的领域，把 RL 的既有成功搬进语言模型，这就是 o1 式推理模型时代的思路；本讲两部分：算法篇（PPO→GRPO 及变体）+ 案例篇（DeepSeek R1、Kimi K1.5、Qwen 3 三个开源推理模型）([0:10])

### 二、PPO：从策略梯度到 clip 目标([0:10])

- 策略梯度(policy gradient)：想最大化期望奖励 E_{z~pθ}[R(z)]，梯度=E[R(z)·∇log pθ(z)]——按奖励正负升降序列概率，数学恒等、随时合法；但纯 on-policy：每走一步梯度都要重新 rollout 采样，而 RL 里贵的恰恰是 rollout（推理慢，assignment 5 会亲身体会），于是希望一次采样、多次更新([0:10])
- TRPO：允许样本「过期」——从旧策略 pθ_old 采样，用重要性采样(importance sampling)对比率做修正，同时把新策略拉住、不让它离旧策略太远，防止奖励估计失真；式中的 A_t 是比原始奖励方差更低的优势量([0:15])
- PPO：在 TRPO 上再简化——不玩 KL 约束，直接把新旧策略概率比截断(clip)在 1±ε：跑太远就不再有额外收益，算法自然没有动机漂移太远；是非常成功的通用 RL 算法（OpenAI DOTA Five 等真实 RL 环境也在用）([0:15])
- 概念不复杂，复杂的在 A_t：它要靠第二个神经网络——价值函数(value function)——估计期望回报来降梯度方差；实现层面另有名场面的「37 个 PPO 实现细节」博文：不同变体在 RL 基准上分数各异，甚至有论文发现实现「错」到策略梯度都算不对、反而效果更好([0:15])

### 三、PPO 实现剖析：大家为什么想换掉它([0:20])

- 全景：RLHF 版 PPO 同时要养 reward model、value model、GAE（广义优势估计，generalized advantage estimation）与策略语言模型四套机器；但外层循环其实平淡：采 rollouts → 算 loss → backward → 带 clip norm 的梯度步，与普通语言模型训练无异([0:20])
- loss 两块：价值函数损失（让 value 逼近实际回报，职责是降方差）+ PPO clip 策略损失；典型 cliprange=0.2，即新旧策略似然比被允许在 0.8~1.2 之间移动([0:20])
- rollouts 部分就是推理：从当前策略采样、再评估这些样本的 logprobs；唯一小坑是 value/reward/policy 三个模型的 tokenizer 可能不同，要做对齐([0:20])
- 视角纠偏：语言模型 RL 其实是 contextual bandit（上下文老虎机）——prompt 进、回答出、立即给分，没有状态转移、没有环境探索；reward shaping（奖励塑形）即逐 token 构造损失：KL 正则按每个 token 计，而「任务是否完成」的真实奖励只放在最后一个 token([0:20])
- 实现怪癖：真正的 KL 公式在数值上不稳（比率变负时常常撞上），实践里把 log 比率项 clamp 到 0——严格说那就不再是 KL，只是某种近似([0:20])
- 策略梯度可以写成 R(z)·log pθ(z) 的加权损失直接喂 autograd，对 R 有隐式 stop gradient（assignment 5 也要这么做）；最后一块机器 GAE：折扣优势估计，λ 与 γ 调偏差-方差权衡——但直接取 γ=λ=1，整坨东西退化成「带基线的策略梯度」（R 减隐含价值），效果也不错；训练预期是奖励上升、含负 KL 的奖励分量下降的平滑曲线，而非狂野 RL 曲线([0:25])

### 四、GRPO：用组内基线替换价值模型([0:25])

- 为什么找替代：PPO 能用但是头野兽；最烦的是价值模型——它通常和策略一样大，显存直接翻倍；DPO 又不合适：数学题判对错没有天然成对结构，且 DPO 本质是离线算法（先囤 pairs 再更新，虽然能改成在线但不常这么用）([0:25])
- GRPO 的核心一步：保留 PPO 的 clip 与策略更新框架，把 GAE 整个删掉，优势直接换成组内 z-score——A_i =（r_i − 组内均值）/ 组内标准差([0:25])
- 组(group)=同一道题的 G 个候选回答；题目有难有易，组内均值天然构成「题目难度」基线——与 leave-one-out 策略梯度(RLOO)一脉相承；基线只在同题内做，跨题之间除了策略一起更新外互不干扰([0:30])
- 两个细节：GRPO 的 KL 估计是控制变量(control variate)版——(π_ref/π_θ)·log 比率再减 1，期望不变、方差更低，是值得记住的 KL 采样估计技巧；若每条样本只更新一步（纯在线），clip 全部消失，算法就是「乘以 A_i 的策略梯度」——简单到极致([0:30])
- 实现与直觉一致：外层循环算每条 rollout 的奖励 → 组内归一化（减均值、除标准差）→ 算 KL → 梯度更新；除标准差处要加 1e-4 的 fudge factor 防止除零（assignment 5 里同样要加）([0:30])
- DeepSeekMath 结果：RFT / online RFT（只用答对的自己输出做 SFT）是弱基线；GRPO + 结果级奖励（只判对错）就很能打；过程级奖励（PRM 逐步打分）当时更好——这条线索在 R1 一节会回收([0:30])

### 五、Dr. GRPO：两个实现层面的偏差([0:35])

- GRPO 与 PPO 唯一实质差异就是优势估计；回到策略梯度定理：减去任何与当前样本无关的常数或随机变量(baselining)都仍是合法梯度，目的是降方差——而 GRPO 的 z-score 有两处越出了这个契约([0:35])
- 越界一：除以标准差——标准差小 ⇔ 组内奖励全 0 或全 1 ⇔ 题目过易或过难，此时优势反而被放大，等于给能力两端的题加权；作者认为这拖慢收敛（folk theorem:RL 真正想要的是「有点能做但没全会」的中间难度，课程要喂对难度），至少它破坏了策略梯度的合法性([0:40])
- 越界二：长度归一化（把量按输出长度除）——负奖励下最优策略是把回答拖长稀释惩罚，答对则要尽量短才能最大化正奖励 → 激励模型「觉得要错就写最长」，是非常坏的偏置([0:40])
- 修正之后：GSM8K 等任务奖励不降，但输出长度不再无限增长、稳定在某个目标值——由此得出有趣猜想：大家热炒的部分超长 CoT 可能是 GRPO 实现细节的产物，而非长思考本身是性能必需（尚未完全证实）([0:40])

### 六、案例一：DeepSeek R1——极简配方复刻 o1([0:40])

- 背景与意义：R1 与 Kimi K1.5 几乎同期、结果相当，是同一问题的两条平行路线；R1 是一篇 arXiv 论文引发社会现象的奇观（NVIDIA 市值应声蒸发数千亿美元）；它用极简配方复刻 o1 的全部质性特征——没有搜索、没有 PRM，打破「推理模型必须有一堆复杂组件」的想象，并给出 SFT 与 RL 交互的重要洞见([0:40])
- R1-Zero=受控实验：在只做了预训练+mid-training 的 DeepSeek V3 上直接上数学 RL（无任何 RLHF/指令微调）；奖励只有两项：二值准确性奖励（答案对/错）+ 格式奖励（强制把 CoT 装进 <think> 标签）——格式奖励看着无关紧要，却是整套路由能跑通的关键一环；结果已逼近 o1([0:45])
- R1-Zero 的两个「现象」与冷峻解读：CoT 长度随训练可预测增长（论文称「学会更努力地思考」）与 aha moment（回溯）——Dr. GRPO 作者反驳：长度增长源于有偏目标而非内在机制，基模型 V3 本来就会偶尔输出「aha」；未必是涌现奇迹，但模型确实很强([0:45])
- R1 正式版配方：先用长 CoT 数据做 SFT 初始化（数据来源与过滤方式论文里非常模糊）→ RL（同 R1-Zero + 语言一致性奖励，防 CoT 训着训着语言混杂——网上 Grok 3 CoT 突然切中文即同类现象）→ 末端常规后训练；「要上高级 RL 就先来点 SFT」是反复出现的模式([0:45])
- 两个补充：长 CoT SFT 比想象便宜——拿 Gemini 2.0 Flash Thinking 的 1,000 条长思维链微调 Qwen 2.5 就能大幅提升数学基准，说明基模型早已具备思考能力、SFT 只是把它们引出来；语言一致性奖励是刻意用零点几分的性能换 CoT 可读性（讲者解读），供应商给原始 CoT 做摘要也是同一动机([0:50])
- 成绩单与科学贡献：英语任务全面追平 o1、代码略逊；蒸馏——近百万条 CoT 微调 Qwen，32B 模型 AIME 从 ~50% 提升 25 个百分点以上；贡献三点——正面证明「结果奖励+GRPO」够用，两个负结果：PRM（过程奖励模型）与 MCTS（搜索）都没能帮上忙（DeepSeekMath 时还看好 PRM,到 R1 放弃），结果奖励+RL 至今仍是最强范式([0:55])

### 七、案例二：Kimi K1.5——平行解法与推理成本控制([1:00:00])

- 头条：Kimi K1.5 在多个重要任务上追平或超越 o1；骨架与 R1 相同(SFT+RL)，RL 算法不同，数据构建讲得更细——Qwen 3 后来直接沿用其做法([1:00:00])
- 数据策展：LLM 自动打标、按领域平衡多样性；剔除多选题与判断题（太好猜、太好 hack）；只留「答案短、可用 regex 或 LLM 判分」的可验证题；pass rate 过滤——用未做 RL 的 SFT 模型每题生成答案，只保留 best-of-8 全错的题（8 中 0 对才算有难度）；SFT 数据同样语焉不详（「prompt engineering」,显然是蒸馏来的）([1:00:00])
- RL 算法：从 DPO 式推导出发（非参数最优策略、reward 写成策略之比）但不接 Bradley-Terry，而是给「最优策略应满足的等式」两边加平方损失；取完梯度神似 GRPO：策略梯度 + batch 内均值基线 + 平方 log 比率正则（替代 clip）——两种算法的趋同演化(convergent evolution)；且没有除以标准差([1:00:00])
- 长度奖励：要 ship 推理模型，推理成本才是真金白银的约束，CoT 必须压缩；按 batch 内长度 min-max 区间给每个回答定位 λ，答对则奖励含 λ（越短越好）、答错则被推向区间中段；该奖励若一开局就加，会把 RL 锁死在「答案全错、CoT 压到极短」的局部极小——先无约束 RL，后期再开启([1:05:00])
- 课程与奖励实现：题目按难度标注、由易到难排课，并按 1−成功率 采样（全对的题永不再采）；代码题=标准答案+自动生成测试用例；数学题=用奖励模型判断模型输出与人工标准答案是否等价（别人用 regex/SymPy,他们用模型——意外但可行，本质是高级字符串匹配、准确率很高）([1:05:00])
- 基础设施（RL 推理论文里少见的系统讨论）：RL 想吃满 GPU 比预训练更难——rollout 推理本身慢，RL worker 与推理服务间要来回传权重，长 CoT 让 batch 长短悬殊；方案是 RL worker 与推理 worker 分工 + vLLM 推理（先用 dummy weights 起服务、再想办法注入真权重，每轮迭代拆掉以释放显存）；用 NCCL 集合通信向 vLLM 注权的实验 API 参数未文档化、尚不成熟([1:05:00])
- 训练动态与问答：逐迭代 scaling 良好；响应长度像 Dr. GRPO 修正版一样在目标长度企稳（其算法本身无变长偏置），而非 vanilla GRPO 式无限增长；多奖励怎么合？全部加权相加、权重凭下游表现经验调——format reward 可视为 shaping/surrogate 奖励，只是引出长 CoT 的手段([1:10:00])

### 八、案例三：Qwen 3 与本讲总结([1:10:00])

- 流水线：base → 长 CoT SFT → 推理 RL → thinking mode fusion（思考模式融合）→ RLHF → 蒸馏；延续 R1 的顺序（推理 RL 在前、RLHF 在后、蒸馏最后）([1:10:00])
- 数据：沿 Kimi 用 best-of-n 过滤难度（未 RL 的基模型 n 次内能答对即删）；对与验证集过相似的样本去污染；长 CoT SFT 数据人工过滤「真推理 vs 蒙对」([1:15:00])
- 惊人的小数字：推理 RL 只用了 3,995 条样本就取得可观增益——可验证奖励 RL 可以非常样本高效（与「少量样本即可指令微调/蒸馏长 CoT」的旧结果同调，但能否继续随规模受益仍未知）([1:15:00])
- thinking mode fusion：要单套参数同时支持思考/非思考——用带 <think>（正常 CoT）与 <no_think>（直接给答案）标签的数据再 SFT；还附赠思考预算旋钮：模型持续思考时可在特定字符串处截断思考、直接作答——从单个模型得到干净的 test-time scaling，可设最大思考预算并优雅降级([1:15:00])
- 消融揭示权衡：通用任务与指令遵循上，推理 RL、融合、通用 RL 一路全都有帮助；但数学/STEM 上通用 RL 反而伤害思考模式、只利好非思考模式——通用对齐与数学代码能力之间存在取舍，留待未来模型绕开([1:15:00])
- 本讲总结：RLHF 无法在噪声成对偏好上无限爬坡 → 换到无法 reward hacking 的窄领域直接 RL；GRPO=策略梯度+组内好基线，简单到足以支撑整个推理模型浪潮；野外的成功配方已有很多，共同点是「策略梯度+好基线+正则」，差异在实现细节([1:15:00])

## 核心概念速查

- **DPO**：成对偏好 + 非参数假设把 reward 写成策略之比，代入 Bradley-Terry；梯度=按隐含 reward 误差加权地升好降坏
- **SimPO**：DPO 变体——更新按长度归一化 + 去掉参考策略
- **过优化与校准**：proxy reward 涨而真实胜率先升后平台/回落（人类与含噪 AI 反馈都会出现）；RLHF 优化策略而非分布，温度 1 下过度自信
- **策略梯度**(policy gradient)：E[R·∇log pθ]；减去与样本无关的基线(baseline)仍合法，用于降方差
- **PPO**：重要性采样(TRPO)让旧样本可更新；概率比截断 1±ε 替代 KL 约束；价值函数+GAE 降方差，γ=λ=1 退化为带基线策略梯度
- **contextual bandit**：LLM RL 的真实形态——prompt 进、回答出、立即给分；KL 正则逐 token、真奖励在末 token
- **GRPO**：优势=组内 z-score（同题 G 个回答的 （r_i−均值）/标准差），替换 GAE、免掉价值模型；RLOO(leave-one-out)是其先驱思路
- **控制变量法 KL 估计**：GRPO 的 (π_ref/π_θ)·log 比率 − 1，期望不变、方差更低
- **Dr. GRPO 批评**：除以标准差放大过易/过难题；按长度归一化激励答错拖长——修正后输出长度企稳
- **R1-Zero**：基模型直接数学 RL；二值准确性奖励 + 格式奖励（<think> 标签）
- **语言一致性奖励**：防 RL 后 CoT 语言混杂；用一点性能换可读性
- **PRM / MCTS**：过程奖励模型与搜索式推理——R1 报告的两个负结果
- **Kimi 长度奖励**：答对越短奖励越高；训练后期才开启，防局部极小
- **best-of-8 过滤**:SFT 模型 8 中 0 对的题才保留（Kimi/Qwen 数据策展）
- **thinking mode fusion**:Qwen 3 单模型 think/no_think 双模式；截断字符串=思考预算旋钮

## 自测题

1. GRPO 如何计算某个回答的优势？它与 PPO 最核心的替换是什么？
   > 同一道题采样 G 个回答，优势=（该回答奖励−组内均值）/组内标准差（组内 z-score），用它替换 PPO 的 GAE，从而不再需要价值模型
2. Dr. GRPO 指出 vanilla GRPO 的哪两处实现会引入偏差，各导致什么行为？
   > 除以组内标准差会放大「全对/全错」的过易过难题；按长度归一化让答错的回答靠拖长稀释惩罚、答对的靠缩短涨分——修正后输出长度在目标值企稳
3. R1-Zero 的奖励设计只有哪两项？为什么格式奖励意外地关键？
   > 二值准确性奖励（答案对错）+ 格式奖励（把 CoT 装进 <think> 标签）；格式奖励是长思维链能被 RL 引导出来的关键一环
4. DeepSeek R1 报告里的两个负结果是什么？说明了什么？
   > 过程奖励模型(PRM)与 MCTS 搜索都没能帮助复刻 o1；结果级奖励 + GRPO 至今仍是最强范式
5. Kimi K1.5 如何用 pass rate 过滤训练题？
   > 用未做 RL 的 SFT 模型每题采样，只保留 best-of-8 全错的题——基模型 8 次里有 1 次能对的就算太容易，直接剔除
6. Kimi 的长度奖励为什么不能在训练一开始就加？
   > 早期答案几乎全错，长度奖励会把模型锁进「CoT 压到极短」的局部极小逃不出来；先无约束 RL，后期再开长度奖励
7. Qwen 3 的 thinking mode fusion 做了什么？带来什么推理期新能力？
   > 用带 <think>/<no_think> 标签的数据再 SFT，让单套参数兼顾思考与直答；还能在特定字符串处提前截断思考，实现可调思考预算的 test-time scaling
8. 为什么经过 RLHF 的模型校准会变差？
   > RLHF 优化的是策略而非概率分布，校准不进奖励；温度 1 下模型普遍过度自信——别把 RLHF 模型当校准的概率模型用
