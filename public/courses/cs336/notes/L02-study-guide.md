## 一句话概览

本讲不直接讲 transformer，而是从张量(tensor)一路搭到训练循环，同时建立两套能在餐巾纸上心算的账本：内存核算(AdamW 下每参数约 16 字节)与 FLOP 核算(训练 FLOPs ≈ 6×参数量×token 数)。它是后续 GPU、内核、并行与缩放定律各讲的"会计学"基础，也直接服务于 assignment 1。

## 分节要点(带时间锚点)

### 一、动机：餐巾纸数学(napkin math)与本讲定位
- 开场心算题一：1024 块 H100 训 70B 参数稠密模型、15T token，总 FLOPs = 6×参数×token，按 MFU=0.5 折算约需 144 天([0:00])
- 心算题二：8 块 H100(各 80GB HBM)用 AdamW，每参数需 16 字节(参数+梯度+两个优化器状态)，不玩花活最多训约 40B 参数——激活还没算([0:00])
- 效率是这门课的主线：规模一大，浪费的 FLOPs 直接换算成美元，必须精确知道自己花了多少([0:00])
- 本讲定位：机制(mechanics)= PyTorch 原语，心态(mindset)= 资源核算(resource accounting)；transformer 概念概览留给下一讲，直觉部分暂只给粗轮廓([0:00])

### 二、浮点格式与内存核算
- 张量(tensor)是存储一切的基本单元：参数、梯度、优化器状态、数据、激活都是张量([0:05])
- float32 = 1 符号位+8 指数位+23 尾数位：指数给动态范围(dynamic range)、尾数给分辨率；显存 = 元素个数×每元素字节，GPT-3 前馈层单个矩阵就约 2.3GB([0:05])
- float16 存储减半但动态范围太小：1e-8 直接下溢成 0，大模型矩阵一多就数值不稳定([0:05])
- bfloat16(bf16,2018)：指数位与 FP32 同为 8 位，动态范围不缩、分辨率变粗——深度学习恰好不在乎分辨率([0:10])
- 实践分工：前向/矩阵乘等瞬态计算用 bf16；参数与优化器状态必须留 float32，否则训练崩；FP8(2022,NVIDIA,H100 才支持)更省更快但更糙，分偏分辨率/偏范围两种变体([0:10])
- 按流水线各处(前向/反向/优化器/梯度累积)挑最小够用精度 = 混合精度训练(mixed precision training)，例如注意力留 FP32、普通 matmul 用 bf16([0:10])

### 三、张量的本质：指针、stride 与视图
- 张量默认建在 CPU，必须显式 `.to()` 搬上 GPU；时刻清楚每个张量住在哪，必要时用 assert 确认([0:15])
- PyTorch 张量 = 指向已分配内存的指针+元数据：第 (i,j) 个元素偏移 = i×stride0 + j×stride1,4×4 矩阵 stride 为 (4,1)([0:15])
- 切片 `x[0]`、取列、view、transpose 都只是新视图(view)：共享底层存储、零拷贝，改 x 会连带改 y([0:20])
- transpose 后张量非连续(non-contiguous)，不能再 view；先 `.contiguous()`(此时才真拷贝)，或直接 reshape ≈ contiguous().view([0:20])
- 视图免费，放心多用并命名中间变量；逐元素运算会新建张量，triu 用来造因果注意力掩码([0:20])

### 四、einops/einsum：批量矩阵乘与命名维度
- 语言模型运算对象是 (batch, seq, …) 张量，PyTorch 对前导维逐个广播做矩阵乘([0:25])
- `x @ y.transpose(-2,-1)` 这类负索引易错、注释易过期；einops 受爱因斯坦求和约定启发，给每个维度命名([0:25])
- einsum = 带记账的矩阵乘：输出里没写的维度被求和、写了的被遍历；`...` 代表任意多个广播维([0:25])
- jaxtyping 可把维度写进类型注解(默认不强制,可配检查器)；einsum 配 torch.compile 会自动定归并顺序，效率不输手写([0:25])
- reduce 按名聚合维度；rearrange 是 view 的花哨版：把 heads×hidden 的扁平维拆开、变换完再合回去([0:30])

### 五、FLOP 计数与 MFU
- 术语纪律：FLOPs(小写 s)= 浮点运算次数，硬件速度写 FLOPs/s；量级感：GPT-3 ≈ 3.2e23、GPT-4 ≈ 2e25，欧盟 AI 法案报备线 1e25(美国 1e26 行政令已撤销)([0:30])
- 峰值随数据类型变：A100 312 TFLOP/s;H100 标称 1979 TFLOP/s 是含 2:4 结构化稀疏的星号数(稠密约一半,"只有市场部在用"),FP32 仅 67([0:35])
- 矩阵乘 FLOPs = 2×三个维度之积(每输出元素一乘一加)；其余运算对张量大小近似线性，心算只需盯 matmul([0:35])
- 前向 ≈ 2×token 数×参数量，可推广到 transformer(序列长度不太大时)([0:40])
- MFU(model FLOPs utilization)= 实际有用的模型 FLOPs ÷ 墙钟时间 ÷ 承诺峰值；>0.5 算好、5% 算糟；课上 FP32 matmul 实测约 0.8([0:40])
- MFU 只数"模型有用的 FLOPs"，缓存/重算的优化不受惩罚(另有按真实执行算的 HFU)；bf16 实测更快但 MFU 反降——承诺值偏乐观，要 benchmark 自己的代码；峰值均指 tensor core，PyTorch/torch.compile 默认会用([0:45])

### 六、反向传播的代价：2 + 4 = 6
- 前向：两层线性网络 x(B×D)→W1(D×D)→H1→W2(D×K)→H2→loss，总 FLOPs = 2×总参数量([0:50])
- 反向对每个权重矩阵要算两个类矩阵乘：对 W2 的梯度(H1ᵀ 乘 dH2)+ 继续回传的 dH1(dH2 乘 W2)，各 2×三维之积，合计每层反向 4×三维之积([0:50])
- 总账：前向 2×N×D + 反向 4×N×D = 6×N×D——开场 6ND 公式的出处([0:55])
- 适用前提：每个计算触及"新"参数；参数共享会让一个参数产生大量 FLOPs，公式失效([0:55])
- 作业不必手推梯度，直接用 PyTorch autograd；课上拆开是为了数 FLOPs([0:55])

### 七、参数、初始化与随机性
- 模型参数用 `nn.Parameter` 对象存储([1:00:00])
- 单位高斯乱初始化：输出尺度随 √hidden 维放大，大模型直接爆炸；权重除以 √输入维后输出稳定在 N(0,1) 附近——即(差一个常数的)Xavier 初始化([1:00:00])
- 保险起见可把正态截断到 [-3,3]，免受无界长尾的大值搅局([1:00:00])
- 随机性来源多(初始化、dropout、数据顺序)：每个来源单独固定 seed，可复现、好调试——确定性是朋友([1:00:00])
- 语言模型数据是 tokenizer 输出的整数序列，可存成 numpy 数组；LLaMA 数据 2.8TB 装不进内存，用 np.memmap 映射文件按需加载，再套 DataLoader([1:05:00])

### 八、优化器、总内存核算与训练实践
- 优化器谱系：SGD → momentum(梯度滑动平均,Nesterov) → AdaGrad(按梯度平方累加和缩放) → RMSProp(改用指数平均) → Adam(2014,RMSProp+momentum 合体)([1:05:00])
- 作业 1 自己实现 Adam；课上示范 AdaGrad：继承 Optimizer，state 是 参数→状态 的字典，累加 g²、按 lr·g/√state 更新，step 末尾可释放中间显存([1:05:00])
- 全模型内存账(FP32)= 4 字节×(参数+激活+梯度+优化器状态)，小示例算出 496；transformer 版(注意力、多矩阵)结构相同，留给 assignment 1；训练循环五步：模型→优化器→取数据→forward→backward→step([1:10:00])
- 激活必须存：第 i 层的梯度依赖该层激活；不想存就在反向时重算——激活检查点(activation checkpointing)([1:10:00])
- 长训练必崩：定期把模型+优化器状态+当前迭代数一起存盘，才能无损续训([1:15:00])
- 混合精度收尾：前馈走 bf16/FP8、其余留 FP32(思路可上溯 2017 年,PyTorch 有自动工具)；训练压精度难、推理量化易——部署时再激进量化(冲 int4)；模型设计正被硬件反向牵引([1:15:00])

## 核心概念速查

| 术语 | 一句话解释 |
|---|---|
| FLOPs / FLOPs/s | 浮点运算次数(工作量)/ 每秒次数(硬件速度)；课程禁用大写 FLOPS |
| MFU | 实际有用的模型 FLOPs ÷ 时间 ÷ 硬件承诺峰值，>0.5 算健康 |
| 6ND | 训练总 FLOPs ≈ 6×参数量×token 数：前向 2 + 反向 4 |
| stride | 张量元数据中每维的步长，决定在一维存储上如何定位元素 |
| view / contiguous | 视图共享存储零拷贝；transpose 后非连续，contiguous/reshape 才拷贝 |
| einsum / einops | 用命名维度做矩阵乘与重排，输出未提及的维度被求和 |
| bf16 | 指数位同 FP32(8 位)故动态范围不缩水，深度学习计算的主力精度 |
| 混合精度训练 | 前馈用 bf16/FP8，参数与优化器状态留 FP32 |
| Xavier 初始化 | 权重除以 √输入维，使各层输出方差稳定(差常数版) |
| memmap | 把磁盘文件映射成按需加载的数组，数据装不下内存时用 |
| Adam | RMSProp(指数平均)+momentum(滑动平均)的合体，2014 年提出 |
| 激活检查点 | 反向需要各层激活；不存就在反向时重算，时间换显存 |
| tensor core | GPU 上做矩阵乘的专用硬件，规格表峰值均指它 |
| 2:4 结构化稀疏 | H100 星号峰值的兑现条件，实践中几乎无人使用 |

## 自测题
1. 在 8 块 80GB 的 H100 上用 AdamW、不做任何优化，大约能训多大的模型?依据是哪个数字?
   > 约 40B 参数：AdamW 每参数需 16 字节(FP32 的参数+梯度+动量+方差)，640GB÷16B；激活未计。
2. bf16 与 float16 同为 16 位，为什么深度学习训练选 bf16?
   > bf16 指数位与 FP32 同为 8 位、动态范围不缩水(fp16 会把 1e-8 下溢成 0)，牺牲的分辨率 DL 不在乎。
3. y = x[0] 之后修改 x，为什么 y 也跟着变?
   > 切片只新建视图(view)不拷贝，两者共享同一底层存储。
4. transpose 之后的张量为什么不能直接再 view?怎么办?
   > transpose 后存储非连续，view 要求连续布局；先 .contiguous()(产生拷贝)或改用 reshape。
5. 一个 (B×D) 矩阵乘 (D×K) 矩阵要多少 FLOPs?
   > 2×B×D×K：矩阵乘 FLOPs = 2 乘三个维度之积，每个输出元素一乘一加。
6. 训练 FLOPs 公式 6×参数×token 里的 6 是怎么来的?
   > 前向 2×N×D；反向要算对权重与对激活两组类矩阵乘，共 4×N×D；合计 6。
7. MFU 怎么算?多少算好?
   > 实际有用的模型 FLOPs ÷ 墙钟时间 ÷ 硬件承诺峰值 FLOPs/s；大于 0.5 通常算好。
8. 训练时哪些状态必须留 FP32?哪些可以降到 bf16?
   > 参数与优化器状态(需长期累积)必须 FP32；前向/矩阵乘等瞬态计算可用 bf16。
