## 一句话概览

本讲讲"怎么知道一个语言模型好不好"：评测看似只是跑分脚本，实则决定模型往哪里建。课程从 perplexity 讲到 MMLU 家族、指令遵循、agent 与安全基准，最后落到评测危机的根源——污染、可博弈性与"我们评的到底是模型还是方法"。

## 分节要点(带时间锚点)

### 一、开场：评测危机

- 评测的日常呈现形态：论文报 MMLU Pro / MATH 500 / GPQA 等基准分数，HELM 把多个标准基准聚合成排行榜；Artificial Analysis 把智能指数与每 token 价格画成帕累托前沿(Pareto frontier)——O3 最强但最贵；Open Router 用真实路由流量做排名，赌"人们选的就是好的"；Chatbot Arena 用网民成对偏好出 ELO 榜([0:00])
- 还有最非正式的一路：有人在 X 上晒"模型能做到这件神奇的事"的 vibes 截图，也是一种质量信号([0:00])
- Karpathy 的判断：当前处于评测危机(evaluation crisis)——MMLU 这类老基准要么饱和要么被博弈(gamed)，Chatbot Arena 也有问题；模型一大堆、分数一大堆，但哪个才是正确的评测方式并不清楚([0:00])
- 课程定位：评测表面上"给固定模型跑个脚本"，实际上深刻——开发者都在追踪同一批基准，你追踪什么、想把什么数字刷上去，就会塑造你建模型的方式；评测是未来走向的先行指标([0:05])

### 二、为什么评测：目的决定方法

- 机械流程很简单：拿现成模型→投 prompt→收响应→算指标→取平均；但"没有唯一正确的评测"，一切取决于你要回答什么问题([0:05])
- 四类典型目的：用户/企业做选购决策(Claude vs Grok vs Gemini vs O3 用哪个)；研究者问原始能力与是否在科学进步；政策与商业要客观了解收益与伤害；模型开发者要反馈来改进模型(分数低了就干预、升了就保留)([0:05])
- 四步框架：①输入(prompt 从哪来、覆盖哪些用例、有没有尾部与困难样本)②怎么调用模型(few-shot / zero-shot / 思维链(chain of thought)，每个选择都给指标引入大量方差；要不要工具、RAG)([0:05])
- 评测对象之辨：评的是语言模型还是整个系统(含脚手架 scaffolding)?开发者关心前者，用户只关心系统整体——这个区分贯穿全讲([0:10])
- 输出怎么评：参照答案(reference)干不干净；代码生成用 pass@1 还是 pass@10；成本在排行榜里常被边缘化(榜首可能比第二名贵 10 倍，所以要看帕累托前沿)；错误代价并不均等；开放式生成("写个关于斯坦福的精彩故事")没有 ground truth 可依([0:10])
- 结果怎么解读：拿到 91 分算不算好、该不该上线?模型是真泛化还是训练集混入了测试集(train-test overlap)?研究对象是模型还是方法——学术论文的产出往往是新方法，评方法需要严格的控制变量，否则多数评测都没意义([0:10])
- 学生问答：输入要不要适配模型?多轮对话与红队(red teaming)必须适配(红队要高效找尾部事件)，但一旦适配，跨模型比较就失去公平基准——这是权衡([0:10])

### 三、Perplexity 的兴衰

- 定义回顾：语言模型是 token 序列上的分布，困惑度(perplexity)衡量模型给某个数据集(通常是验证集)分配的概率高低；2010 年代的标准玩法是 Penn Treebank / Wikitext / One Billion Word 上分 train/test，挑架构刷数字([0:15])
- 2010 年代的代表成果：Google 用合适的架构+规模把困惑度从 51 压到 30，是"挑战问题"式的巨大进步——大数据集上游戏从"防过拟合"变成"能否把数据拟合起来"([0:15])
- GPT-2 改写了游戏规则：40GB Reddit 链接网页文本训练，不做任何微调直接在标准困惑度基准上测——明确的分布外(OOD)评估，靠 web text 的广度换泛化；在很小的 Penn Treebank 上竟然超过 SOTA，One Billion Word 上仍落后(数据够大时直接训练胜过迁移)([0:20])
- 训练测试重叠(train-test contamination)自此成为大问题：常见做法是去掉与测试集有 13-gram 重叠的文档，但近复述、翻译成外语(语义等价、字面零重叠)都会漏网；反过来引用测试集的训练文档又造成假阳性—— 宁可保守删多，也别高估模型([0:20])
- GPT-2/GPT-3 之后社区转向下游任务准确率，但困惑度仍值得保留：信号更平滑(拿到每个 token 的 logits 概率，而非"对/错"的粗粒度)、scaling 曲线拟合更优雅、且是"全能"的——每个 token 都在打分，而任务准确率可能"答对但理由错"，尤其当数据集可被博弈时；也可以在下游任务上 condition 于 prompt 算答案概率，直接为任务拟合 scaling law([0:25])
- 困惑度的黑盒陷阱：做排行榜时你必须信任提供方输出的概率真的归一——若有 bug 全部报 0.8，分数会假性优秀；只有拿到全部 logits 才能自行验证求和为 1，困惑度评测"一不小心就会搞砸"([0:25])
- 困惑度至上主义(perplexity maximalists)的论证：最优困惑度下界是真实分布 t 的熵，p=t 时达到，分布匹配到位就解决一切任务；反驳是这会浪费概率质量在不重要的部分(人类并不盲配每个 token)。但有一点很硬：只要 train/test 分开，困惑度不是一个可被博弈的量——这在基准遍地被刷分的时代反而稀缺([0:25])

### 四、知识型基准：MMLU 家族

- 形似困惑度的任务已全部饱和：LAMBADA(挑战长上下文补词)、HellaSwag(按各候选概率选常识续写，只有按 token 数归一的小细节)基本被模型"碾压"；且 HellaSwag 源自 WikiHow，训练集里留有形似考题的近重复——又是污染([0:30])
- MMLU(2020,GPT-3 刚出)：57 个学科、全部多选题、直接从网络收集；名字虽叫"理解"，Percy 认为测的其实是知识(他自认语言理解不差，但答不好外交政策冷知识)；当时 GPT-3 few-shot 只有 45%——指令微调出现之前，base 模型不给示例就会开始续写新题，必须 few-shot 提供格式([0:30])
- HELM 实操演示：排行榜→点进单个学科(如计算机科学)→逐题查看输入、选项、模型预测与对错，连实际喂入的 few-shot prompt 都可见；评测透明可核查是 HELM 的设计初衷([0:35])
- 学生问答：few-shot 示例的选择、顺序、格式都显著影响分数(分类任务全给正例，模型就只会输出正例)；指令微调后 zero-shot 成为主流，few-shot 退化为"给格式+省 token"的手段，in-context learning 更多是识别任务而非从 5 个例子里学会美国历史([0:35])
- 解读要点：MMLU 满分 90+ 里有 prompting / 思维链 / 集成的抬分空间；更重要的是，MMLU 对 base 模型反而是好评测——不专门刷题、只靠泛泛预训练就能高分，说明真有"智能"；专门按 57 学科刷题刷出来的高分，对泛化能力的指示就弱得多——数字的意义取决于被评的是什么、训练集是什么([0:40])
- MMLU-Pro：去掉噪声题、选项从 4 个加到 10 个拉低准确率，配合思维链评测(许多题不推理一步根本出不了答案)，让前沿模型避开饱和区，各模型提供方纷纷跟进([0:40])
- GPQA：把难度抬到 PhD 级——领域博士出题→专家验证反馈→修改→再验证，非专家即使带 Google 搜 30 分钟也只得约 30%(故名 Google-proof)，专家约 65%；GPT-4 当时 39%，一年后 O3 到 75%([0:45])
- GPQA 的两个隐患：黑盒模型可能暗中联网搜索(要选"不搜索"模式，且只能信任提供方)；人类基线也可能偷偷用 LLM——"Google-proof"防不住模型本身([0:45])
- Humanity's Last Exam(HLE)：多模态、多选+简答，仍是有唯一正确答案的考试型题(重要的局限——现实里很多问题模糊无标准答案)；用奖金池+共同作者署名征集题目，再用前沿模型过滤"太简单"的题；O3 约 20%；但开放征集自带偏差——出题者都是深度接触 LLM 的圈内人，只能保证"难"，不保证代表任何真实问题分布([0:50])

### 五、指令遵循与开放式回答

- ChatGPT 之后四年，评测重心转向指令遵循(instruction following)：没有固定任务，用户描述一次性的新任务，模型直接做；核心难题"如何评开放式响应"至今未解([0:50])
- Chatbot Arena：网民随机输入，匿名拿到两个模型的回答，选更好的那个；按成对偏好算 ELO 出排名。优点：数据是活的、动态流入，永远新鲜，ELO 天然容纳新模型进场([0:50])
- Arena 的丑闻："The Leaderboard Illusion" 论文揭露部分厂商拿到特权访问、可以多重提交等不对称待遇；一旦上榜成为 PR 目标，古德哈特定律(Goodhart's law)"凡是可度量的就会被钻空"立即应验；另一次生问题是"随机网民"这个分布到底服务谁的真实需求([0:55])
- IFEval：专测约束遵循——至少/至多几句、必须用哪些词、什么格式，约束全部可以写脚本自动验证；但要清醒：它只评"是否遵守约束"，完全不评内容语义(10 个词的狗故事，只数字数不看好坏)，是"部分评估"且可被博弈，指令本身也不太现实(规划日本旅行但不许用逗号)([0:55])
- AlpacaEval：用 LLM 当裁判(LLM-as-a-judge)算对某个参考模型的胜率；天然有偏(问 GPT-4"你更喜欢你自己的输出还是别人的")；2023 年小模型靠"回答越写越长"骗裁判，后来加了长度修正(length-corrected)；它与 Arena 相关——即信息基本等价，但胜在全自动、可复现、便宜([0:55])
- WildBench：语料来自真人-机器人对话(发布机器人收集)，judge 配 checklist 强迫逐项检查；它也与 Arena 相关——这个领域里"评测的评测"最后都在向 Arena 的相关性看齐([1:00:00])

### 六、Agent 与纯推理基准

- Agent = 语言模型 + 脚手架(scaffold,决定怎么调用模型的程序逻辑)；任务需要用工具(跑代码、上网、计算器)且要迭代多轮([1:00:00])
- SWE-Bench：给定代码库+GitHub issue 描述，agent 要产出让单元测试通过的 PR；最流行的 agent 基准([1:00:00])
- CyBench：网络安全夺旗(CTF)——agent 拿到服务器，要黑进去取回密钥；标准架构是"思考→规划→生成命令→执行→更新记忆→迭代"，直到超时或完成；准确率约 20%，且难度以人类首次解出时间为标尺(最长一题人类花了 24 小时，O3 能解出人类需要 42 分钟的题)([1:00:00])
- MLEBench：75 个 Kaggle 竞赛，agent 读赛题与数据、写代码、训模型、调参、debug、提交；拿到奖牌级成绩的比例尚不足 20%([1:00:00])
- ARC-AGI：2019 年(pre-LLM)的异类——纯图形模式补全，没有语言、没有任务描述，刻意剥离知识、只考"纯推理"(被认为更接近智能的本义:奖励创造性与解决新问题的能力，而非"我上过网所以会")；人类轻松、GPT-4 接近 0 分([1:00:00])
- O3 在 ARC-AGI 上表现强劲，但代价是每道题数百美元量级的算力；ARC-AGI-2 更难，继续追踪([1:05:00])

### 七、安全基准与越狱

- 安全评测类比汽车碰撞测试与食品安全的"强制评级"，但 AI 太早期，"安全"到底是什么尚无共识；现有工作先看两类([1:05:00])
- HarmBench：整理 510 种有害行为，逐条诱导模型看是否服从(如给二甲基汞的制备指南)；多数模型达标，DeepSeek V3 则很乐意配合([1:05:00])
- AIR-Bench：把"安全"落地——从各国监管框架与公司政策中提炼分类体系(taxonomy)再建基准，让抽象概念锚定在法律与政策上；Claude 拒答较得体，另一些模型偏弱([1:05:00])
- 越狱(jailbreaking)是"元安全"：在开放权重的 Llama 上自动优化出对抗后缀，竟能迁移攻破 GPT-4——"毁灭人类的分步计划"+乱码后缀让 ChatGPT 照答；例子虽不现实，但"安全干预可被绕过"在高风险场景就是隐患([1:10:00])
- 只按拒绝率排安全榜有个坑：全部回答"我不知道"就能登顶；安全评测必须搭配能力评测，证明模型"既安全又有用"([1:10:00])
- 部署前测试(pre-deployment testing)：美英等国安全研究所与 Anthropic、OpenAI 等厂商建立自愿协议——发布前给早期访问、跑安全评估、出报告反哺部署决策；目前不具法律约束力([1:10:00])
- 安全是强语境的：随法律、政治、社会规范与国别变化；且安全≠拒绝——医疗等高风险场景的幻觉也是安全问题，减少幻觉同时提升能力与安全；进一步要区分能力(capability,能不能做)与倾向(propensity,会不会去做)：API 模型只看倾向即可，开放权重模型连能力也算风险(微调几下就能关掉安全训练)；还有双用途困境——CyBench 既度量网络攻击风险，同样的 agent 又能帮你在部署前做渗透测试([1:10:00])

### 八、现实性、有效性与评测对象

- 现实性鸿沟：标准化考试离真实用例很远；但"真实流量"也不干净——很多人只是来捣乱发垃圾；真正的区分是 quizzing(用户知道答案，在考你)vs asking(用户不知道答案，真要你的输出)——asking 才产生真实价值，而标准化考试全属 quizzing([1:15:00])
- Anthropic 的做法：用语言模型对真实对话做硬聚类(hard clustering)，得到用户用 Claude 的分布——编码居首；部署方天然拥有真实用例的评测数据(付费用户至少在乎回答)([1:15:00])
- MedHELM：此前医疗基准都脱胎于标准化考试；这里请 29 名临床医生列出执业中真实能用上语言模型的场景，得到 121 个临床任务(写病历、规划治疗等)组成套件；涉及患者数据不能公开托管——真实性与隐私相互矛盾([1:15:00])
- 有效性(validity)与污染检测：如今模型在互联网上训练、数据不公开，靠基准设计者划 train/test 的时代结束了；Route 1 是用探针推断(模型对测试集特有的选项顺序表现出偏好=很可能见过)；Route 2 是立社区规范——像报告置信区间一样强制报告"测试集是否在训练集中"，现状是厂商偶尔做、绝非惯例([1:15:00])
- 数据集质量问题：SWE-Bench 有错已修复；许多基准都带错——math/GSM8k 那些 90+ 分数背后约一半是标签噪声(label noise)，修完数字还会涨([1:15:00])
- 收尾之辨：过去评的是方法(固定 train/test,新架构/新学习算法，数字代表方法好坏)；今天评的是系统(anything goes)，对用户有用但难做算法结论；两个例外仍评方法——"Not all GPT is a speedrun"(固定数据集，最小时间达到目标 loss)与 DataComp(选数据达到目标准确率)；最后一句忠告：定义好游戏规则，想清楚你的评测到底为了回答什么([1:20:00])

## 核心概念速查

| 术语 | 一句话解释 |
|---|---|
| 评测危机(evaluation crisis) | MMLU 等老基准饱和或被博弈、Arena 受质疑，分数遍地却不知该信谁 |
| 训练测试污染(train-test contamination) | 测试集内容混入训练数据；常规对策是 13-gram 去重，但近复述与翻译会漏 |
| 困惑度(perplexity) | 模型对验证集分配概率的度量；平滑、关注每个 token，且只要 train/test 分开就不可博弈 |
| 困惑度至上主义(perplexity maximalism) | 主张分布匹配(压到真实分布的熵)终将解决一切任务 |
| MMLU | 2020 年 57 学科多选题，知识型标准考试，GPT-3 few-shot 当时 45% |
| MMLU-Pro | MMLU 去噪+10 选项+配思维链，让前沿模型避开饱和区 |
| GPQA | PhD 级"Google 搜不出"问题：非专家带 Google 约 30%，专家约 65% |
| HLE(Humanity's Last Exam) | 征集制多模态超难题，前沿模型过滤后 O3 约 20%；难但无分布代表性 |
| Chatbot Arena | 匿名成对偏好+ELO 的动态榜；"The Leaderboard Illusion" 曝出特权与多重提交 |
| IFEval | 可脚本验证的约束遵循；只评约束不评语义，是可博弈的部分评估 |
| AlpacaEval | LLM 当裁判对参考模型的胜率；有长度修正版，结论与 Arena 相关 |
| WildBench | 真人-机器人对话语料+checklist 式 LLM judge |
| SWE-Bench | 给 issue 产出 PR、以单元测试通过为准的 coding agent 基准 |
| CyBench | 网络安全夺旗基准；以人类首次解出时间为难度标尺 |
| MLEBench | 75 个 Kaggle 竞赛自动参赛，奖牌率尚不足 20% |
| ARC-AGI | 无语言纯图形推理，人类轻松、GPT-4≈0、O3 强但每题数百美元 |
| HarmBench / AIR-Bench | 有害行为诱导测试 / 从监管与政策提炼 taxonomy 的安全基准 |
| 越狱(jailbreaking) | 对抗性 prompt 绕过安全训练，且能从开放权重迁移到闭源模型 |
| 能力 vs 倾向(capability vs propensity) | 能不能做 vs 会不会去做；API 模型只看倾向，开放权重两者都算风险 |
| quizzing vs asking | 用户考你 vs 用户真求助；标准化考试属前者，真实价值在后者的分布里 |

## 自测题

1. 本讲反复强调"没有唯一正确的评测"，那么设计一个评测前首先要明确的是什么?
   > 要回答的问题是什么——用户选购、科学研究、政策了解收益伤害还是开发者拿反馈迭代，目的决定了具体评测设计
2. 为什么 scaling 研究仍然偏爱困惑度而非下游任务准确率?
   > 困惑度给出每个 token 的细粒度概率、信号平滑便于拟合 scaling 曲线，且关注所有 token，不会像任务准确率那样"答对但理由错"
3. 在黑盒排行榜上报告困惑度有什么任务准确率没有的特殊风险?
   > 你必须信任提供方输出的概率真的归一，若其有 bug 对什么都报 0.8，分数会假性优秀；只有索要全部 logits 才能自行验证求和为 1
4. GPQA 为什么被称为 Google-proof?非专家与专家各能拿约多少分?
   > 非专家即使带 Google 搜索 30 分钟也只能得约 30%，领域专家约 65%，因为问题被设计成搜索引擎搜不出答案
5. "The Leaderboard Illusion" 论文揭露了 Chatbot Arena 的什么问题?
   > 部分厂商获得特权访问、可多重提交等不对称待遇；上榜成为 PR 目标后 Goodhart 定律应验，评测协议被动机污染
6. IFEval 这类约束遵循基准的根本局限是什么?
   > 只用脚本验证表面约束(字数、句数、禁用词、格式)，完全不评内容语义，因此只是可被博弈的部分评估
7. 只按"拒绝有害请求的比例"排安全榜会出现什么荒谬结果?该怎么办?
   > 一个对所有请求都回答"我不知道"的模型就能登顶；安全评测必须搭配能力评测，证明模型既安全又有用
8. 能力(capability)与倾向(propensity)有何区别?为什么开放权重模型两者都构成风险?
   > 能力指"能不能做到"，倾向指"会不会去做"；API 模型只需管倾向，但开放权重模型可以被微调轻易去掉安全训练，所以能力本身也是风险
