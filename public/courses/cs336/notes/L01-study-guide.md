## 分节要点(带时间锚点)

### 一、为什么开这门课：抽象泄漏与工业化断层

- 现状危机：研究者与底层技术不断脱节——八年前大家自己实现并训练模型，六年前至少下载 BERT 微调，如今很多人只靠提示(prompt)专有模型过活([0:00])
- 语言模型的抽象是泄漏的(leaky)：不像编程语言/操作系统那层语义清晰，它只是字符串进、字符串出，出错时无从得知内部发生了什么([0:00])
- 工业化断层：GPT-4 传 1.8 万亿参数、训练约 1 亿美元，xAI 集群 20 万张 H100，且官方明说出于竞争与安全不披露任何细节——前沿模型对个人遥不可及([0:00])
- 课程哲学：理解它就必须亲手构建它(from scratch)；本期扩招 50%，全部讲座放上 YouTube 让全世界学([0:00])

### 二、小规模训练的两个陷阱与三类知识

- 陷阱一(餐巾纸数学)：注意力与 MLP 的 FLOPs 占比随规模剧变——小模型两者大致相当，175B 时 MLP 主导；在小规模死磕注意力优化，到大规模会被洗掉([0:05])
- 陷阱二(涌现能力)：训练 FLOPs 增长初期任务准确率纹丝不动，跨过阈值才突然出现上下文学习(in-context learning)等现象——困在小规模会误判「语言模型不行」([0:05])
- 三类知识：机制(transformer、模型并行，可全教)、心态(榨干硬件、认真对待 scaling,可全教)、直觉(哪些数据与建模决策有效，只能部分教)——合计约 2.5/3([0:05])
- 认知边界的诚实样本：SwiGLU 激活效果好、被广泛采用，但原论文结论坦言「除神圣恩典(divine benevolence)外无可解释」——有时只能让实验说话([0:05])

### 三、bitter lesson 的正解：效率

- 常见误读：「规模就是一切，算法无用，砸钱即可」；Percy 的正解是规模下的算法(algorithms at scale)才重要([0:05])
- 模型质量 = 算法效率 × 投入资源；规模越大效率越关键——上亿美元的训练任务经不起失败重跑，利用率上前沿实验室远超学界([0:10])
- OpenAI 2020 论文：2012–2019 年在 ImageNet 上达到同等准确率的算法效率提升 44 倍，快于摩尔定律——算法进步真实且可度量([0:10])
- 全课的元问题：给定算力与数据预算，能构建的最好模型是什么?本质是单位资源准确率，任何规模都成立([0:10])

### 四、七十年速史：从 Shannon 到开放权重

- Shannon 最早用语言模型估计英语的熵；此后 LM 长期只是机器翻译、语音识别等大系统里的组件([0:10])
- 冷知识：2007 年 Google 已在约 2 万亿 token 上训练 5-gram 模型——token 数超过 GPT-3，只是 N-gram 没有今天的有趣现象([0:10])
- 2010 年代配齐全部原料：首个神经语言模型(Bengio 2003)、seq2seq、Adam、注意力机制→transformer(2017)、混合专家与模型并行探索——2020 前一切就绪([0:10])
- 基础模型(foundation models)路线：ELMo/BERT/T5 证明「大规模预训练+下游适配」可行，当时引发巨大热情([0:10])
- OpenAI 补上关键一块：极致工程+拥抱缩放定律(scaling laws)的心态→GPT-2/GPT-3；随后 Eleuther、Meta、BLOOM、DeepSeek、AI2 等走向开放模型([0:15])
- 开放的三档：闭源(仅 API)、开放权重(open weights,架构细节齐全但不给数据)、开源(open source,权重+数据+诚实论文)——论文永远替代不了亲手构建([0:15])

### 五、课程五大支柱与作业地图

- 总纲：一切围绕效率——「给你一份 Common Crawl 和 32 张 H100 跑两周，你该做什么?」分词器、架构、系统、数据全是围绕这个问题的设计决策，课程据此分五大支柱([0:25])
- 支柱一 基础(basics)：跑通完整管线=BPE 分词器+transformer 架构+训练；2017 年后的增量改进累加起来差异显著——SwiGLU 激活、旋转位置编码(RoPE)、RMSNorm、归一化位置调整、混合专家(MoE)替代稠密 MLP、滑动窗口/线性注意力防平方爆炸、GQA/MLA 低维注意力、状态空间模型及混合架构；作业 A1 在无脚手架条件下实现全栈(BPE 是公认耗时大户)，在 TinyStories/OpenWebText 上以 H100 跑 90 分钟压 perplexity 上排行榜；训练侧用 AdamW，调好与没调可差一个数量级；难度上 A1/A2 最重、A3 喘口气、A4/A5 低一档([0:25])
- 支柱二 系统(systems)：GPU=片上计算阵列+片外显存，数据移动是最大瓶颈(仓库/工厂类比)，靠融合(fusion)与分块(tiling)提利用率，kernel 用 Triton 写；多卡经 NVLink/NVSwitch 互联、跨卡数据移动更慢，需在卡间摆放参数/激活/梯度，即数据并行与张量并行([0:35])
- 推理与 A2：推理分预填充(prefill,并行处理整个 prompt,compute-bound)与解码(decode,自回归逐 token 生成，难以打满算力、memory-bound)两阶段；投机解码(speculative decoding)让小模型草拟多 token、大模型并行验收；全球推理总成本已超过训练；A2 实现 kernel+数据并行+FSDP 缩水版，并养成 benchmark+profile 的习惯——没有 profiler 就是盲飞([0:35])
- 支柱三 缩放定律(scaling laws)：给定 FLOPs 预算该选多大模型?Chinchilla 最优经验法则=训练 token 数≈20×参数量(如 1.4B 配 28B tokens)，局限是不计推理成本；A3 提供配额制「训练 API」，在有限预算内跑小模型、拟合缩放定律、外推提交大规模超参，体验前沿实验室式的实验取舍([0:40])
- 支柱四 数据(data)：模型能力基本由数据决定(多语数据→多语能力、代码→代码能力)；先评估后策展——perplexity、MMLU 式标准考试、指令跟随评估、系统级评估；数据不会从天上掉下来，Common Crawl 大部分是垃圾，HTML→文本是有损转换，要做过滤(训分类器)与去重，前沿实验室已在买数据；A4 从原始 Common Crawl 做起，分类器+去重+token 预算内压 perplexity([0:45])
- 支柱五 对齐(alignment)：base model 只有「补全下一 token」的原始潜力，对齐=指令跟随+风格控制+安全拒答；两阶段走：监督微调(SFT)用提示-回复对，约千条样本即可教会指令跟随；再从反馈学习——偏好数据(A/B 评分)走 DPO，数学/代码等形式化验证器或学习型验证器走强化学习，GRPO 是 DeepSeek 对 PPO 的简化(去掉价值函数)；A5 实现 SFT/DPO/GRPO 并评估([0:50])

### 六、效率视角统一一切：计算受限 vs 数据受限

- 本课与多数研究者处于计算受限(compute-constrained)机制：数据多、算力少，一切设计决策服务于榨干硬件([0:55])
- 四个具体体现：数据激进过滤(不在坏数据上浪费算力)；tokenization 本身是效率妥协(字节级最优雅但当前架构算不动)；基本只跑一个 epoch(急着见更多新数据)；缩放定律=用小算力定大超参；此外对齐上投入资源可以换来更小的 base model([0:55])
- 两条路径：用例窄→小模型+对齐/微调即可做好；用例宽→可能绕不开训练大模型([0:55])
- 前沿实验室正转向数据受限(data-constrained)机制，设计决策将随之改变：单 epoch 不再合理(为何不多跑几轮或更聪明地重复利用)，连架构都可能变(transformer 本身就是算力效率的产物)——效率不变，决策随机制而变([0:55])

### 七、分词：三种朴素方案的失败清单

- 定义：tokenization 是 Unicode 字符串与整数序列之间的双向转换，encode/decode 必须可逆，词表(vocab)大小=token 可取的整数范围；空格属于 token 且按惯例放在词首(源自 BPE 预切分器的设计)，因此 hello 与 hello 是不同 token——别扭但就是如此([1:00:00])
- 数字被从左到右机械切分，没有千位分组等语义；建议玩一玩在线 tokenizer playground(如 GPT-4o 分词器)建立体感，Karpathy 的分词视频也值得看([1:00:00])
- 方案一 字符级：字符直接映射码点(code point)，A=97、🌍=127757；缺陷=词表巨大且给每个字符均匀分配槽位，稀有字符浪费词表预算，压缩率仅约 1.5([1:05:00])
- 方案二 字节级：UTF-8 把一切字符串转成字节序列，词表仅 256、无稀疏问题——最优雅，但压缩率=1(一字节一 token)导致序列过长，注意力平方复杂度下是效率灾难([1:05:00])
- 方案三 词级：正则表达式切词(经典 NLP 做法，GPT-2 的预切分也用正则)，「自适应」的直觉正确，但词表无界、新词要吃 UNK，perplexity 还会算错——不是我们要的东西([1:10:00])

### 八、BPE：在语料上训练分词器

- 血统：Gage 1994 年的数据压缩算法→Sennrich 等引入神经机器翻译(解决词级 UNK 之痛)→GPT-2 带入语言模型时代；核心洞察=不预设切分规则，直接在原始语料上训练分词器，常见序列自动合并为单 token、稀有序列保持多 token([1:10:00])
- 算法：文本转字节序列后，每轮统计相邻 token 对出现频次，把最高频对合并成一个新 token(编号从 256 起)；讲座示例 the/the/hat 中先合并 (116,104)→256，再 (256,101)→257，再 (257,32)→258——序列不断收缩即压缩率上升([1:10:00])
- 工程细节：GPT-2 先用词级正则做预切分(pre-tokenization)，再对每段独立跑 BPE，课程作业沿用此法([1:10:00])
- encode=转字节后按训练时的先后顺序重放各次合并；decode=查 vocab 拼回字节再解码为字符串，严格可逆([1:15:00])
- 讲座参考实现刻意朴素：encode 遍历全部 merges 应改为只处理相关对，还有 special tokens 等细节；作业=从零实现并做快(可并行化，自由发挥)([1:15:00])
- 结课预告：下讲 PyTorch 积木与 FLOPs 记账；Percy 的愿望是有朝一日不必再讲这节课——字节级架构成熟的那天([1:15:00])

## 核心概念速查

| 术语 | 一句话解释 |
|---|---|
| BPE(Byte Pair Encoding)| 1994 年数据压缩算法：反复合并语料中最高频相邻对生成新 token；GPT-2 起成为语言模型分词标准 |
| 缩放定律(scaling laws)| 损失随参数/数据/算力呈可预测的幂律，支持小规模实验外推大规模超参 |
| Chinchilla 最优 | 训练 token 数≈20×参数量；只管训练最优，不计推理成本 |
| 涌现能力(emergent abilities)| 规模跨过阈值才出现的能力(如上下文学习)，小规模完全测不出 |
| bitter lesson | 正解是「规模下的算法」(algorithms at scale)：规模越大，算法效率越值钱 |
| 压缩率(compression ratio)| 字节数÷token 数：字节级=1、字符级≈1.5、BPE≈1.6(讲座示例值) |
| 码点(code point)| Unicode 字符的整数编号(A=97、🌍=127757)，字符级分词直接当 token ID |
| UTF-8 | Unicode 最常用变长编码，每字符 1–4 字节，是字节级与 BPE 的底层表示 |
| 预切分(pre-tokenization)| BPE 前用正则把文本切段(GPT-2 做法)，空格按惯例归到词首 |
| SwiGLU / RMSNorm / RoPE / MoE | 现代 transformer 相对 2017 原版的四个高频替换件：激活、归一化、位置编码、稀疏专家 |
| SFT(supervised fine-tuning)| 用提示-回复对做监督学习，约千条样本即可让 base model 学会指令跟随 |
| DPO | 只凭 A/B 偏好数据完成对齐的简化算法，不需要完整强化学习 |
| GRPO | DeepSeek 对 PPO 的简化：去掉价值函数，适配验证器类反馈信号 |
| prefill / decode | 推理两阶段：prefill 并行吃 prompt(compute-bound),decode 自回归逐 token(memory-bound) |
| 投机解码(speculative decoding)| 小模型草拟多个 token，大模型并行验证一次性接受，推理加速 |
| Triton | OpenAI 的 GPU kernel 编程框架，课程用它实现融合与分块 |
| FSDP | 全分片数据并行，把参数/梯度/优化器状态切到各卡；课程作业做缩水版 |
| base model | 只会补全下一 token 的预训练模型，具有原始潜力，须经对齐才可用 |

## 自测题
1. Percy 说开设 CS336 的「真正原因」是什么?(相对 GPT-4 给出的那些泛泛理由)
   > 研究者与底层技术日益脱节且抽象泄漏，只有亲手从零构建才能支撑根本性研究
2. 「苦涩的教训」(bitter lesson)常被误读成什么?Percy 给出的正确解读是什么?
   > 误读为规模万能、算法无用；正解是规模下的算法(algorithms at scale)才重要，规模越大算法效率越关键
3. 为什么在小规模上做实验可能得出误导性结论?讲中给了哪两个例子?
   > 小模型不代表大模型：注意力/MLP 的 FLOPs 占比随规模变化；涌现能力(如上下文学习)在小规模完全测不出
4. 课程声称能教的三类知识是什么?各自能教到什么程度?
   > 机制(可全教)、心态(榨干硬件+认真 scaling,可全教)、直觉(哪些数据与建模决策有效，只能部分教)
5. 给定 FLOPs 预算时，Chinchilla 最优给出的经验法则是什么?它忽略了什么成本?
   > 训练 token 数≈20×参数量(如 1.4B 参数配 28B token)；它不考虑推理成本
6. 推理的 prefill 与 decode 两阶段有何区别?为什么 decode 是 memory-bound?
   > prefill 并行处理整个 prompt(compute-bound)；decode 自回归逐 token 生成，难以打满算力，瓶颈在数据搬运
7. 字符级、字节级、词级三种朴素分词方案各自的致命缺陷是什么?
   > 字符级：词表巨大且稀有字符浪费预算；字节级：压缩率=1、序列过长撞上注意力平方复杂度；词级：词表无界、新词变 UNK
8. BPE 训练的每一轮做什么?encode 新字符串时如何使用训练产物?
   > 每轮统计相邻 token 对频次、把最高频对合并为新 token；encode 将输入转字节后按训练时的顺序重放各次合并
