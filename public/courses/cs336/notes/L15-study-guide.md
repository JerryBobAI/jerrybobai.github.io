## 一句话概览

post-training 第一讲：预训练把能力「打包」进参数，本讲讲怎么让它开箱即用——前半是监督微调(supervised fine-tuning, SFT)，看 FLAN/OpenAssistant/Alpaca 三种指令数据范式、长度偏差与「教出幻觉」陷阱、安全微调与 mid-training 规模化；后半是人类反馈强化学习(reinforcement learning from human feedback, RLHF)，从模仿 p* 转向最大化奖励，经成对反馈训练奖励模型，走完 Bradley-Terry → PPO → DPO 的推导主线。

## 分节要点(带时间锚点)

### 一、课程定位：从 GPT-3 到 ChatGPT([0:00])

- 课程只剩两讲、都是 post-training：此前聚焦预训练的大系统与数据，现在要把预训练模型变得有用且安全——本讲 SFT + RLHF + 安全对齐，下一讲是可验证奖励强化学习(reinforcement learning from verifiable rewards, RLVR,推理/数学训练)([0:00])
- 本讲主题即「GPT-3 → ChatGPT」这一跃：GPT-3 预训练算力惊人但不能遵循指令、不成产品；ChatGPT 能同时执行一大块嵌套复合指令并零样本输出 matplotlib 代码(Sparks of AGI 的例子)——今天觉得理所当然的能力，正是 post-training 造出来的([0:00])
- 上线后安全与内容审核成为一等公民：防滥用(诈骗、虚假信息)与产品化(没人愿为充满毒性的产品付费或挂广告)；ChatGPT 成功的重要原因就是周围有严格的护栏(guardrails)([0:00])
- 心智模型：预训练把能力打包进参数——模型内在地会推理、答题，但开箱不做；post-training 就是收集想要的行为数据、训练模型开箱即做，核心问题有三：行为数据长什么样、有多难收集；算法上怎么用(专家示范可模仿,成对偏好反馈 A>B 怎么用)；如何规模化([0:00])
- 本讲结构照搬 InstructGPT 三步流程：SFT(专家示范)→ 奖励模型 → 强化学习；今天业界的 post-training 管线大体仍沿自这篇论文([0:05])

### 二、SFT 数据三范式：FLAN、OpenAssistant、Alpaca([0:05])

- 数据在这里格外重要：post-training 用非常小的数据量去精确塑造行为，指令微调(instruction tuning)数据有噪声就会训出奇怪行为；三种代表性构造范式逐一细看([0:05])
- FLAN(Google)：把现有 NLP 任务数据集(natural instructions V2、T0-SF、adversarial QA、话题分类等)聚合成一个大混合数据集——写亮点摘要、四选一话题分类、Enron 邮件「写主题行」、E2E 数据库条目转餐厅描述——数据近乎免费、量大，但能明显看到「动手术」的痕迹，不像真实聊天交互([0:05])
- Alpaca(Stanford)：早期用语言模型生成指令数据的尝试——以少量人工种子指令为种子让 LM 自我扩充，再用 InstructGPT 填回复；输入更像真实 chatbot 交互、回复几乎都是长自然语言，但指令偏短、多样性不足([0:10])
- OpenAssistant：ChatGPT 发布后网友热情人工编写的指令数据——查询更复杂、回复极其详细甚至带引用，质量高但收集难([0:10])
- 课堂练习一：全班众包一条指令回复——结果与真实众包一致：长回复很难写、敷衍与玩梗混杂，最认真的长回复多半出自 ChatGPT([0:10])
- 教训(AI feedback 的根源)：动机再强的标注者也在时间约束下写不出长而详细的回复，而 GPT-4o 对同一提示的回复又长又好——让人类产出这种质量的激励设计极难，这就是用 LM 生成/精炼训练数据的流行原因([0:15])

### 三、数据质量两难：长度偏差与「教出幻觉」([0:15])

- 设计指令数据要同时想：长度与风格的巨大差异、量 vs 质的取舍、以及安全数据——课堂练习采的只是能力数据，不会教会模型拒绝恶意指令([0:15])
- 长度偏差是「房间里的大象」：2023 年初指令数据集综述(Wang 等)显示各数据集输入/输出长度差异巨大；人类评估者与 AI judge 都强烈偏爱列表、约 60-70% 偏好更长输出——但你想优化的应是减少幻觉与真实能力，不是文风([0:15])
- 对冲之道：长度等因素对 MMLU 这类基准影响不大，简单指令数据即可普遍超过 base 模型——chat 式评测(Chatbot Arena、AlpacaEval)与基准测试各有位置，用多样的评测策略避免被单一偏差带偏([0:15])
- 「高质量数据」陷阱(OpenAssistant 的 monopsony 例子)：微调模型复现带引用的长回复，同时教两件事——知识关联(monopsony ↔ 某文献,好)与「复杂问题末尾要补一个引用」的通用样式(模型不知道这文献时 = 教它编造)；两种机制叠加，哪个占主导取决于模型是否真知道该事实([0:15])
- John Schulman 论点：SFT 数据远超预训练模型自身能力时，模型学到的捷径是「编一个以凑齐类型签名(type signature)」——输出结构必须填满 token，幻觉比缺失「损失更小」；已知事实易复现、未知事实难学；对策是 on-policy RL——只对模型真知道的给训练信号，不知道就教它说「我不知道」([0:20])
- 反直觉结论：一个完全正确、内容丰富的指令数据集可能反而有害；对强 teacher 蒸馏、比模型博学的人类标注都要同样小心；这件事在 instruction tuning 层面优化起来非常 messy，开放文献里尚未解决([0:20])

### 四、安全微调与 SFT 规模化：mid-training([0:25])

- 安全微调的核心权衡：该拒绝的 vs 看起来危险其实无害的(「how to kill a Python process」)——纯 instruction tuning 里让模型理解这种细微差别很难，靠精心策划的小数据集平衡；研究表明混入少量安全数据(甚至约 500 条)就能让模型遵循安全指南([0:25])
- instruction tuning 三条经验：惊人强大(标准数据集 + 合理超参就能得到接近 Llama/ChatGPT 的行为,离优化到位当然还远)；「高质量数据」的定义复杂、需仔细推理；少量数据在该阶段有巨大杠杆([0:25])
- 方法上：学界的答案就是梯度下降；前沿实验室则把 SFT 规模化到像预训练管线——指令数据也是 token 序列，完全可以混进预训练，预训练与指令微调的边界日益模糊([0:25])
- mid-training 配方：纯预训练后，在预训练尾段(学习率退火/decay 阶段)大量混入高质量与指令数据，最后再做一小轮 SFT；好处是规避灾难性遗忘(catastrophic forgetting)、数据利用更深；miniCPM 公开了两阶段配方，decay 阶段混 Wikipedia、Code SFT、UltraChat、Stack Exchange QA、Evol-Instruct 等；副作用：「base model」一词越来越可疑——新发布的 base 大概率已隐性经历过指令数据阶段，混合比是各家机密([0:30])
- 问答要点一：citation 幻觉问题 mid-training 治不了——它无条件放入数据点，只有「先知道模型知不知道」的自适应方案才行；而预训练用静态数据集、无法做反应式更新，这类方案本质上要 RL([0:35])
- 问答要点二：训练中放「自查知识」的 thought token ≈ Quiet-STaR/STaR 式的强化学习；emoji 问题说明 instruction tuning 可靠教会的是输出的 style/type signature，能否教到更多取决于数据量与预训练；小规模指令数据很难教会新知识，规模化且多样的 mid-training 才开始能教([0:40])

### 五、概念转变：从模仿分布到最大化奖励([0:40])

- 概念转变(讲者刻意放慢)：生成式建模的世界里只有 p*——补全从某个参考分布(互联网 + 标注者数据的混合)抽出，目标就是模仿它；RLHF 的世界里不再关心匹配任何分布，只找策略 p(y|x) 最大化奖励 r(y,x)——语言模型从分布模型变成策略(policy)([0:40])
- 转向 RL 的理由一(成本)：模仿需要从 p* 采昂贵的 SFT 样本——专家写长回复极难(课堂练习已体会)，前沿实验室在 post-training 数据上花数百万美元；RL 只需要奖励的测量值([0:40])
- 理由二(生成-验证差距,generator-validator gap)：人不一定与自己的生成一致——学生论文里一位职业自由撰稿标注者显著偏好 AI 写的摘要(「自己写时觉得得堆华丽辞藻,读 AI 的反而更顺」)；验证比生成便宜、甚至质量更高([0:45])
- 本讲后半路线图：RLHF 数据收集要注意什么、两个代表算法 PPO 与 DPO(PPO 细节留到下一讲)、以及 RLHF 的种种坑([0:45])

### 六、成对反馈与奖励模型：数据收集的现实([0:45])

- 管线：模型自己生成输出(RL 术语的 rollout)→ 两两比较 A/B 哪个好 → 训练奖励模型(reward model)给每个输出内部打一个标量分 → 以它为奖励做 RL([0:45])
- 标注指南长什么样：InstructGPT 公开了少数材料——三支柱 helpful(清晰回答真实意图,如 football 别默认美式)/truthful(不幻觉)/harmless(不毒性不 NSFW)；泄露的 Google Bard 指南结构类似(helpfulness/style/分档评分)，标注者每题仅约 1 分钟；InstructGPT 经 Scale 与 Upwork 只收了约 40 人，以今天的标准小得惊人([0:45])
- 课堂练习二(5 分钟做 pairwise)：只有个别人核查了事实与数学；更长的含幻觉回复得票反而更多；更「结论确定」的数学题其实推错了结论——验证要把长回复拆成一条条 claim 逐个核对，极度劳动密集，Google Bard 新闻正是「标注者每题 1 分钟」；教训：高质量可查证的标注者难得、时间压力下人不查证、在线问卷会被人整卷丢给 GPT-4 抄答案(见过与 GPT-4 一致率 95%+ 的标注者)，外包标注还有定价与伦理问题(living wage)([0:50])
- 对齐在管线末端、却强烈影响行为：研究发现 InstructGPT 的主观立场偏向东南亚宗教——查其附录，标注者是菲律宾/孟加拉人 + 17% 美国人，旁证吻合；另一研究(Heisking/Blunsom/Bartolo)显示众包工人不大关注事实性、更关注格式——标注者不同，同样的问题得到不同的反馈([0:50])
- AI feedback 兴起：GPT-4 成对反馈与人类间的一致率相当且便宜得多；UltraFeedback 是流行的开源 off-policy RLHF 数据集；Zephyr-7B(Hugging Face)项目从人力收集转向 GPT-4 反馈后效果更好；Tulu 3(AI2)用多模型生成回复 + LM 评 chosen/rejected；奠基作是 Anthropic 的 constitutional AI；两个常踩的坑：LM judge 对自己输出的自偏好(self-preference)，以及长度始终是混杂因素([0:50])
- 问答摘要：off-policy = 反馈采自别的模型(告诉你「没到过的地方的地形」)，on-policy = 采自自己的输出(告诉你如何精化自己)；用已知答案的提示做对齐?数学等可验证域可以(下一讲 RLVR)，开放域多正确答案难判定，给标注者看专家回复等 UI 干预有帮助但非银弹；模型自精化的信息论上限很高(它吞过整个预训练语料)，能榨出多少是经验问题([1:00:00])

### 七、RLHF 目标与 PPO([1:05:00])

- 优化目标(InstructGPT 式 2)：最大化奖励 r，减 β·KL(RL 策略‖SFT 参考模型)——RL 时别离起点太远，KL 项至今是标配；再加 γ 项在 RL 中继续混预训练目标以防灾难性遗忘(很多人不做第二步)([1:05:00])
- 奖励的世界假设：每个可能输出的序列都有一个未观测的标量奖励 r；人做成对比较时，按两序列奖励差做 logistic 抛硬币——这就是人类偏好的 Bradley-Terry 模型；我们只想输出 r 最大的序列，却只能观测到带噪成对比较([1:05:00])
- PPO 阶梯之基础：对期望奖励取梯度 → 策略梯度定理/REINFORCE：∇ = E[r·∇log p_θ(z)]——正奖励上权重、负奖励降权重，上过 RL 课都见过([1:05:00])
- 阶梯之二 优势(advantage)：梯度公式里可以减掉任意常数、甚至任意状态相关的基线而不改变期望——得到方差缩减版的奖励，即 advantage([1:05:00])
- 阶梯之三：想一次 rollout 采样后多走几步梯度(近似 off-policy)→ TRPO：用重要性加权(importance weighting)修正陈旧样本、并显式约束留在原策略附近；PPO 走最后一步：不显式加 KL 约束，直接裁剪(clipping)概率比率，自然激励策略不跑远([1:10:00])
- 去掉 PPO 的尝试与结局：chosen 前置 good token/rejected 前置 bad token 再条件生成(不太行)；只训 preferred 输出(不太行)；用奖励模型做 best-of-n 采样再 SFT(还行但不惊艳)；真正留下的是 DPO——去掉奖励模型与重要性比率，回到最简单的监督式：好样本 log loss 正梯度、坏样本负梯度([1:10:00])

### 八、DPO：把 RL 问题变成最大似然([1:10:00])

- 出发点：同一个 InstructGPT 目标(奖励 + 对参考模型的 KL)；第一步假设策略 π_θ 不是神经网络而是任意函数——非参数(non-parametric)假设下可直接写出最优策略的闭式解：π ∝ exp(r)·π_ref([1:10:00])
- 反解隐含奖励：从闭式解解出用策略表达的 r(x,y)——于是「策略」与「奖励」一一对应，RL 目标里的奖励可以整体替换成策略的函数([1:12:00])
- 合体：把隐含奖励代回 Bradley-Terry 成对比较似然(出自 Stiennon 论文)，最小化该损失 = 找「隐含奖励最可能生成这些成对比较」的策略——RL 问题就此变成最大似然(maximum likelihood)问题，与预训练概念上同型，只是最大化的对象是成对比较的概率([1:12:00])
- 三步总结：非参数假设 → 用策略参数化奖励 → 用监督损失优化；讲到此收尾，RLHF 的剩余内容下一讲开头继续([1:13:00])

## 核心概念速查

- **监督微调**(supervised fine-tuning, SFT)/ 指令微调(instruction tuning)：在(指令, 回复)对上做梯度下降；可靠教会输出的 style/type signature，是否教到能力本身取决于数据量与预训练
- **FLAN**：聚合现有 NLP 任务数据集造指令数据——免费量大但不自然、带「手术」痕迹
- **Alpaca**：种子指令 + LM 自我扩充 + 强模型填回复；像聊天但指令短、多样性低
- **OpenAssistant**：网友人工编写的高质量指令数据——查询复杂、回复详尽带引用
- **教出幻觉**：SFT 数据超出模型自身知识(如强加引用)会教出「编一个以凑齐 type signature」的捷径；对策是只对模型知道的内容给训练信号(on-policy RL / 「我不知道」数据)
- **长度偏差**：人类与 AI judge 都偏爱列表与更长输出(约 60-70% 偏好长)；对 MMLU 类基准影响不大，需多样评测对冲
- **安全微调**：该拒绝 vs 过度拒绝的权衡；混入少量(约 500 条)精心策划数据即可见效
- **mid-training**：预训练尾段(退火阶段)混入高质量/指令数据 + 收尾小轮 SFT；规避灾难性遗忘，使「base model」称呼变可疑
- **AI feedback**：用 LM(如 GPT-4)生成回复或成对反馈——与人类一致率相当且便宜；注意自偏好(self-preference)与长度混杂；代表数据/项目：UltraFeedback、Zephyr、Tulu 3、constitutional AI
- **off-policy / on-policy**：反馈采自别的模型 = off-policy(看别人地形)，采自自己的输出 = on-policy(自我精化)
- **奖励模型**(reward model)：从成对比较学出的标量打分器，给 rollout 打分供 RL 最大化
- **Bradley-Terry 模型**：假设每序列有未观测标量奖励，成对选择按奖励差做 logistic 抛硬币
- **策略梯度 / REINFORCE**:∇ E[r] = E[r·∇log p_θ(z)]，正奖励上权重、负奖励降权重
- **优势**(advantage)：减掉任意(状态相关)基线后的方差缩减版奖励，梯度期望不变
- **TRPO / PPO**：TRPO 用重要性加权 + 显式 KL 约束支持多步更新；PPO 改为裁剪概率比率、隐式留在原策略附近
- **DPO**：非参数假设下最优策略 ∝ exp(r)·π_ref，反解隐含奖励代回 Bradley-Terry 似然——RL 变成监督式最大似然；好样本正梯度、坏样本负梯度

## 自测题

1. InstructGPT 的 RLHF 目标函数里，KL 项与 γ 项各起什么作用?
   > KL 项约束 RL 策略别离 SFT 参考模型太远(至今标配)；γ 项在 RL 中继续混预训练目标以防灾难性遗忘(多数实现不做)
2. 为什么说「完全正确且内容丰富的 SFT 数据」也可能有害?
   > 数据超出模型自身知识时(如要求附引用)，模型学到的捷径是「编一个以凑齐输出结构」而非知识本身，反而在教它幻觉；只有模型真知道该事实时才会学成正确检索
3. 长度偏差为什么是指令数据的「房间里的大象」?如何对冲?
   > 人类与 AI judge 都偏爱列表和更长输出(约 60-70% 偏好长)，但这与真实能力无关；用基准(MMLU)与 chat 评测(Chatbot Arena/AlpacaEval)结合的多样评测策略对冲
4. 从 SFT 转向 RLHF 的两大动机是什么?
   > 一省成本：不必从 p* 采昂贵的专家长文示范，只需奖励测量值；二是生成-验证差距：验证比生成便宜甚至质量更高(职业写手也偏好 AI 写的摘要)
5. Bradley-Terry 模型如何把成对比较翻译成奖励?
   > 假设每个序列有未观测标量奖励 r，标注者在 A、B 之间按奖励差做 logistic 抛硬币；奖励模型据此从带噪成对比较反推每个输出的分数
6. PPO 相对 REINFORCE 加了什么?TRPO 与 PPO 的差别又是什么?
   > PPO 用 advantage(可减任意基线的方差缩减奖励)替代原始奖励；TRPO 用重要性加权 + 显式 KL 约束支持多步更新，PPO 改为直接裁剪概率比率、隐式留在原策略附近
7. DPO 推导的三步是什么?它最终把 RL 问题变成了什么问题?
   > 非参数假设下最优策略闭式解 ∝ exp(r)·π_ref → 反解出用策略表达的隐含奖励 → 代回 Bradley-Terry 似然做监督优化；RL 变成最大似然问题(最大化成对比较的概率)
8. off-policy 与 on-policy 的成对反馈各告诉你什么?
   > off-policy 数据采自别的模型，告诉你「没到过的地方的地形」；on-policy 数据采自自己模型的输出，告诉你如何精化自己
