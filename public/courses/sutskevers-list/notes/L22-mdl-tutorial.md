# L22 · MDL 教程 — 学到的规律，就是省下的比特

《A Tutorial Introduction to the Minimum Description Length Principle》(2004) · Peter Grünwald（CWI，阿姆斯特丹） · [arXiv:math/0406077](https://arxiv.org/abs/math/0406077)

（本文收入 MIT Press 文集《Advances in Minimum Description Length: Theory and Application》，即文集头两章：第一章概念综述，第二章数学处理。MDL 作为一套归纳推断方法由 Rissanen 于 1978 年提出——这篇教程是它公认的标准入门。）

## 1. 一句话

MDL 给「什么是好模型」换了一把可计算的尺子：**总码长 = 描述模型花的比特 + 在该模型下描述数据花的比特，求和最短者赢**。奥卡姆剃刀说了几百年「简单的更好」，这是它第一次变成一条逐模型可算的判据；也是「学习即压缩」这句话的严格出处——**学到的规律，就是你能省下的比特。**

## 2. 它之前的世界：拟合最好的模型，偏偏最差

统计学习的老大难：过拟合。摆一排候选——一次、三次、十次、二十次多项式——在训练数据上算拟合误差，挑误差最小的？必翻车：二十次多项式能把 10 个点穿得严丝合缝，误差为零，但对下一个点一无所知。**训练误差最小 ≠ 泛化最好**，在 2000 年前后已是常识。

常识有了，原则没有。当时手里的选择手段各有残缺：

- **人工正则**：给复杂度加惩罚项——惩罚系数多大？魔法数字，逐任务手调
- **交叉验证**：劈一块数据留作裁判——但它是**事后裁判**，只报告哪个候选赢，不给「为什么」，更不生产「该怎么造新模型」的原则
- **统计检验**：那套假设检验语言处理「模型选择」非常别扭

缺一条**第一性判据**：不靠手调、不靠留出集，从原理上回答「模型 A 和 B 谁该赢」。

钩子在这里：你以为过拟合的病灶是「参数太多」，其实病灶是**账没算全**——只算了「数据拟合」一段，漏了「模型本身也要花比特」另一段。参数多不是罪，为参数付的比特账才是。

## 3. 核心思想

### 3.1 两段码：先说你选了谁，再说数据长什么样

MDL 的出发点是通信场景：我观测到数据 D，要把它**完整地**传给你。直接发原始数据比特最多；想省，就得利用数据里的规律——我先把规律提炼成模型，然后分两段发送：

```
第一段码：你选了哪个模型        L(H)    ← 模型自身的描述长度
第二段码：该模型下数据的残差    L(D|H)  ← 用模型做预测,只补纠错部分
────────────────────────────────────────────
总码长 = L(H) + L(D|H)                 ← MDL 最小化的对象
```

工程语汇类比：**第一段是 schema，第二段是 diff**。传一个数据集，先传格式定义，再传压缩内容——schema 越精，diff 越短；但 schema 自己也是字节，写三页 schema 去省十行 diff 就亏了。最优永远在「schema 别啰嗦」和「diff 别太长」之间拉扯。

具体到概率模型：第二段用 Shannon 码，模型给 x 的概率是 P(x|H)，编码 x 花的比特就是 −log₂P(x|H)——**模型越会预测，第二段越短**。于是「总码长最小化」=「模型描述 + 负对数似然」求和最小化：统计教科书里的「负对数似然」，在通信里就叫码长。一个量，两副面孔。

### 3.2 过拟合为什么被自动绕过：两头受罚

回头看那排多项式，MDL 的账本：

```
一次多项式(欠拟合):    L(H) 短,但 L(D|H) 长——残差全是没抓住的规律
二十次多项式(过拟合):  L(D|H) 趋近零,但 L(H) 暴涨——「恰好穿过 10 个点」
                        必须写进系数的高精度小数里,比特一分不少
三次多项式(恰到好处):   L(H) 适中,L(D|H) 只剩噪声级残差 → 总码长最短
```

第二行是整篇的灵魂：过拟合模型省下的第二段码，全部吐给了第一段。**描述长度是守恒的——死记硬背造不出比特**：把数据抄进模型，第一段码至少等于数据本身，净省为零。复杂模型和死记硬背被同一本账惩罚，而「恰到好处」的模型两头都占——MDL 不用任何人调惩罚系数，自动选出**概括力强**的解。

这也给了「简单」一个比「参数个数」细一个分辨率的定义：真正的成本不是参数有几个，而是**把这些参数说清楚要几比特**。参数量相同的两个模型，一个系数全是 0.5 这种「好说的数」，一个系数是 0.48372956…，码长天差地别——后者在为巧合付费。→ L21 里「权重编码」那一笔，就是第一段码在神经网络里的形态。

### 3.3 压缩 ↔ 概率：一枚硬币的两面（一次说清）

Shannon 信源编码定理给了等价：数据服从分布 P 时，最优编码的平均码长是熵 H(P)；反方向，任何一套码长 L(x) 都隐含概率 P(x) = 2^(−L(x))。所以：

```
最好的压缩器 = 最好的概率模型（反之亦然）
```

这不是类比，是等价。它顺手解释了深度学习的日常：语言模型的训练损失 `cross-entropy`，字面意义就是「按你的模型编码数据花的比特数」（→ L12 的损失函数、→ L20 的幂律曲线，量的都是码长）。**训练语言模型 = 训练一台压缩器**——这句话的数学出处就在这里，后面所有篇目直接引用，不再重复。

### 3.4 粗 MDL vs 精 MDL（一段带过）

上面「两段码求和」是**粗 MDL（crude MDL）**：直观好用，理论上有缝——第二段的最优码依赖「恰好这个模型」，第一段给连续参数编码的规矩也要人定。Grünwald 自己推动的**精 MDL（refined MDL）**用通用码（universal code：给一整族模型自动配码，代表构造是 NML——normalized maximum likelihood）把两段都做到信息论最优，缝被缝上。工程直觉用粗版完全够；理论读者知道精版在收拾这些缝即可。全课程用粗版。

## 4. 文章怎么展开论证

（教程类文章，本节按 spec 变体处理——看的不是实验设计，是推进路线。）

1. **从哲学到通信**：先把「奥卡姆剃刀」「简单优先」摆上桌，指出它们不构成判据（「简单」怎么量？），然后切到通信场景——描述长度可数，判据立刻成立。哲学口号换成工程量的那一步，就是这篇的全部门槛
2. **小例子反复验账**：抛硬币序列、多项式拟合这类离散小例子，把「两头受罚」当着读者的面算一遍——教程的说服力全部来自账目本身，一个实验数字都不需要
3. **与既有流派对账**：和贝叶斯模型选择、AIC/BIC 逐一对照——两段码在渐近意义下与 BIC 高度一致（每个实值参数大约付 ½·log₂n 比特的「税」），与 AIC 的分歧则是「一致性」之争的经典案例。MDL 不是另起炉灶，是把各家直觉收进同一本账
4. **通向极限**：把描述长度推到理论天花板——Kolmogorov 复杂度（最短程序长度，→ L25），指出可计算的 MDL 是那个不可计算理想的执行版——为整个理论篇铺路

## 5. 为什么在这份 List 里

1. **给 L23-L26 备好语言**。复杂性理论篇要反复说「这个结构的复杂度」「规律的含量」——量它的尺子就是描述长度：L25 Kolmogorov 把它推到不可计算极限，L24 咖啡自动机用它称「结构的重量」，L26 VLAE 的 ELBO=码长是它的可微化身。没有这一讲，后面全是黑话
2. **「学习即压缩」的说明书**。Ilya 把「无监督学习 = 压缩」讲成第一原理、把语言模型讲成压缩器——严格版本就是 MDL：压缩得好 = 预测得好 = 找到了真规律。它也是「下一 token 预测」这个朴素目标为何能通向智能的第一性解释：逼模型把数据的比特压到最少，就逼它找出全部可利用的规律——省下的每一比特都是规律
3. **统一实践篇的暗线**。L12 的交叉熵、L20 的损失曲线、L21 的权重账——读完这讲回头看，整个实践篇其实一直在量同一样东西。判据级的统一感，是理论篇给实践篇的第一份礼物

## 6. 织进网里

- **← L21 MDL 权重**：分工明确——L21 是 MDL 在神经网络上的具体化（权重付比特账，flat minima = 第一段码省钱的解），本篇是原理本身的教材；先实例后原理，一对读
- **← L12 Transformer / ← L20 Scaling Laws**：`cross-entropy loss` 的通信学身份在此补全——训练曲线的纵轴，字面意义是码长；「loss 下降 = 压缩率上升」从此不再是比喻
- **→ L23 Complexodynamics / → L25 Kolmogorov**：复杂性篇的语言预备——「结构复杂度」用描述长度量，Kolmogorov 复杂度是这个量的不可计算极限
- **→ L26 VLAE**：ELBO = 两段码码长（bits-back 账目）在那一讲展开成可微架构——MDL 的账本直接变成损失函数
- **→ L27 超级智能**：如果压缩通向理解、理解通向能力，「把压缩做到极致的机器会变成什么」是理论篇的收尾之问

## 自测题

1. 两段码各编码什么？MDL 最小化的总量是什么？
   > 第一段编码「你选了哪个模型」（模型自身描述长度 L(H)），第二段编码「数据在该模型下的残差」（L(D|H)，概率模型下即 −log₂P(x|H)）；MDL 选 L(H)+L(D|H) 总和最小的模型。
2. 过拟合模型在 MDL 账本上为什么两头受罚？死记硬背为什么省不下比特？
   > 复杂模型第二段趋零但第一段暴涨（「恰好穿过数据」必须写进参数的高精度小数）；把数据抄进模型，第一段码至少等于数据本身——描述长度守恒，死记硬背造不出比特。
3. 辨析：「模型简单」按什么量才对？按参数个数和按描述长度量，差在哪？
   > 参数个数是粗尺子：同参数量的两个模型，系数全是 0.5 和系数是 0.48372956… 码长天差地别；真正的成本是把参数说清楚要几比特——为巧合付费的解码长暴涨，描述长度细一个分辨率。
4. 「压缩=概率」的等价说了什么？它给语言模型的训练损失赋予了什么身份？
   > Shannon 信源编码定理：最优平均码长=熵，且码长 L(x) 隐含概率 2^(−L(x))——最好压缩器=最好概率模型；`cross-entropy loss` 从此有了通信学身份：按模型编码数据花的比特数，训练语言模型=训练压缩器。
5. 为什么说这一讲是 L23-L26 的语言预备课？Ilya 的哪句第一原理在此拿到严格版本？
   > 复杂性篇「结构的复杂度」都要用描述长度来量（Kolmogorov=不可计算极限、VLAE 的 ELBO=码长=可微化身）；「学习即压缩 / 无监督学习=压缩」在此拿到严格出处——压缩得好=预测得好=找到真规律。
