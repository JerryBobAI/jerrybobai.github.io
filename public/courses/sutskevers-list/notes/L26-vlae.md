# L26 · Variational Lossy Autoencoder — 模型自己决定把信息放哪

《Variational Lossy Autoencoder》（2017, ICLR） · Xi Chen, Diederik P. Kingma, Tim Salimans, Yan Duan, Prafulla Dhariwal, John Schulman, **Ilya Sutskever**, Pieter Abbeel（UC Berkeley + OpenAI） · [arXiv:1611.02731](https://arxiv.org/abs/1611.02731)

注意作者栏：Ilya 是共同作者。这份 List 里他亲手参与的作品不多（L01 AlexNet 是一篇），这一篇离他后来的 GPT 实践反而最近——「学习即压缩」在这里第一次变成可以动手设计、按比特控制的工程。

## 1. 一句话

把 VAE 的弱解码器换成强自回归模型，latent 不会变强，反而会被模型主动「晾在一边」；VLAE 的答案是**给解码器开一个小窗口、物理掐断全局信息的本地通路**——看得不全局，全局结构就只剩 z 一条路可走，于是「模型内部信息放哪」第一次从玄学变成了架构设计参数。

## 2. 它之前的世界：两员大将联手，latent 当场失业

先一句带过背景两件套。**AR（自回归模型）**：逐 token 预测下一个——文本上就是 L06 讲的 char-RNN 一族，图像上是 PixelRNN/PixelCNN（按光栅扫描顺序逐像素生成）。它的局部细节极强、似然（对数据概率的打分）是当时天花板，但它**没有全局概括**：没有一个 z 压缩「这张图整体是什么」，生成全靠逐点采样运气。**VAE（变分自编码器）**：编码器把 x 概括成 latent z，解码器从 z 重建——全局结构有了，但解码器弱（每个像素条件独立的伯努利/高斯），样本糊成印象派。

自然想法：强强联合，VAE 的 z 套上 AR 解码器。前人在序列上试过（Bowman、Chung、Serban 等 2015-2016 年一批工作，战场正是语言建模），结果全军覆没：**latent 被完全忽略**（文献里叫 posterior collapse，后验塌缩——q(z|x) 退化为先验，z 一个比特都不装）。当时的解释是「优化太难」：KL 项早期太强，把 z 掐死了，于是发明了 KL annealing、free bits 一堆补丁。

这篇论文的钩子就在这里：你以为是优化没调好，**其实是数学上的最优解本来就在那里**——不管优化器多努力，答案都是「忽略 z」。论文第 2 节的标题就够挑衅：VAEs do not Autoencode in General，**叫「自编码器」的 VAE，一般不做自编码**。

## 3. 核心思想

### 3.1 损失函数就是码长：ELBO 是一张两段码预算表

勾连 L21/L22 的 MDL：要传输数据 x，好编码方案应该让码长（bits 数）尽量短。VAE 对应一种两段码方案：先发 z 的码，再发「给定 z 时 x 的残差」的码。直接发的效率低；一个叫 **bits-back（读回比特）** 的技巧能省一截——接收方解完 z 后，用同一个 q(z|x) 跑一遍就能把编码 z 时「预支」的随机比特退回来。算完账，净码长恰好是：

```
C(x) = E_q[ log q(z|x) − log p(z) − log p(x|z) ]  =  −ELBO(x)
       └──发 z 的净成本──┘   └─发残差的成本─┘
```

**最小化 ELBO，就是最小化 bits-back 码长**——损失函数是码长，这不是比喻，是等式（论文式 6-7）。再往下推一步（式 8-11）：

```
C(x) = E[−log p(x)] + D_KL(q(z|x) ‖ p(z))  ≥  H(data) + E[D_KL(q ‖ p)]
```

KL 散度（两种分布的差异度量）那一项是**近似的过路费**：q(z|x) 只要不是真后验，每张图就多付 D_KL 比特，一分不免。

### 3.2 learn to ignore 不是 bug，是记账之后的最优解

现在把账合上。解码器什么时候愿意用 z？**z 能省钱的时候**。如果解码器强大到不用 z 也能把 p(x) 建模得很好——AR 解码器正是这种怪物，RNN 逐 token 理论上能表示任意分布——那么用 z 的收益是零，成本却实实在在：q 不等于 p 就要付 D_KL 的过路费。最优解当然是 q(z|x) = p(z)：**z 装零比特**。

论文的关键观察（原文原话）：这个现象「不只源于优化困难——即使把优化问题精确解掉，对绝大多数真后验不可解、解码器足够强的 VAE，最优解依然是忽略 latent」。并且由此引出那条斜体强调的原则，值得整句抄下来：

> **信息偏好（information preference）：解码分布不访问 z 就能本地建模的信息，会被编码在本地，只有剩下的部分才进 z。**

模型会自己决定把信息放哪。信息像水，网络像地形，损失函数是坡度——水永远往免费的低处流，哪条通路便宜走哪条。想让某类信息进 z，光调超参没用，得改地形。

### 3.3 物理掐断通路：窗口化解码器

VLAE 的全部魔法就一句话：**把 AR 解码器的视野关小**。形式上把解码分布写成：

```
p_local(x|z) = Π_i p(x_i | z, x_WindowAround(x_i))
```

每个像素只允许看 z 加上自己窗口内的一小圈邻居（实验里是 6 层 3×3 masked conv 的 PixelCNN，视野就是个小方块）。改动极小，路由彻底反转：

```
普通 PixelCNN:  每个 x_i 能看到全部上文   → 什么都能本地建模 → z 没活干,失业
VLAE 解码器:    每个 x_i 只能看到窗口邻居 → 全局结构本地建不了 → 只能进 z

        ●●●
        ● z ●     ← 窗口内: 邻居像素(管局部纹理/笔画粗细)
        ●●●       ← 窗口外: 一律看不见
        z 是唯一的「全局输入」——物体形状/类别/布局只剩这一条路
```

「哪里漏就堵哪里」：纹理笔画是局部统计，窗口内顺手就建了，让它漏在本地；物体长什么样窗口内根本看不见，只能从 z 进来。**架构每堵一个洞，z 的职责清单就多一行**——这是 L21/L22 的 MDL 思想第一次以「改架构」而非「改目标函数」的方式被执行。

### 3.4 信息路由是个设计空间

窗口只是路由表的一行。论文把整个旋钮盘摊开给你看：

- **窗口大小 = z 的颗粒度**：窗口极小，z 装下几乎全部结构；窗口放大，结构信息逐渐漏回本地，z 只剩最粗的全局轮廓
- **条件喂什么 = 管哪路信息**：想让颜色进 z？颜色局部太可预测，默认漏在本地——把解码器的输入改成灰度图，颜色通路被掐断，颜色立刻被逼进 z
- **分层 latent（全局→局部）**：z 不必只有一个——把不同 z 插在解码器不同深度，底层的管小尺度、高层的管大尺度（论文 3.1 节明确讨论了用降采样视野做多尺度路由的设计；层级 latent 的完整展开后来由 ladder/层级 VAE 一系接棒）。信息按尺度分层入账，就像 JPEG 按频段分配比特——只是这里的分配方案是网络在码长压力下自己谈出来的

顺手记一个呼应：L04 里空洞卷积把「视野」拧向免费扩大，VLAE 把同一个旋钮反向拧——**故意关小视野**。视野是设计参数，两个方向都有戏，这是同一课的正反两面板书。

## 4. 实验逻辑

论文按三个问题组织，环环验账。

**问题一：VLAE 真能学到「只装全局」的有损码吗？** 静态二值 MNIST 上，训练好的 VLAE 平均每张图只往 z 装 **13.3 nats ≈ 19.2 bits**；同款 VAE 换成视野全开的 factorized 解码器，z 要装 **37.3 bits**。19 bits 是什么概念：比一张 28×28 二值图的原始尺寸（784 bits）压缩了约 40 倍，z 里装不下笔画——只有「这是个 4」这个级别的信息。解码可视化（论文 Fig.1）：同一 z 反复解码，全局结构（是 4）完全保真，笔画粗细、二值掩膜的局部样式每次都不一样——**这是一台语义级的「有损 JPEG」，纹理是现编现造的**。

**问题二：码长理论的另一个预言——AF 先验优于 IAF 后验**（AF/IAF：用自回归流给 z 建模的两种等价排布，前者让生成路径更深）。在 Kingma 的 IAF 最强配置上做单点替换：训练 NLL 降 **0.8 nat**、测试 NLL 降 **0.6 nat**。跟「更深的生成路径=更短的码」对得上。

**问题三：加 AR 解码器真能提升密度估计吗？——「混合压缩胜过单打独斗」**。最有说服力的对照是同款 PixelCNN 一加一减 latent 通路：

| 数据集 | 纯 AR（同款 PixelCNN，无 VAE） | VLAE（混合） |
|---|---|---|
| 动态二值 MNIST | 87.53 | **78.53** |
| OMNIGLOT | 95.02 | **90.98** |
| Caltech-101 Silhouettes | 89.26 | **77.36** |

同一个解码器，掐了它全局视野、加一条 z 通路，全面大幅变好——混合的两段码战胜单段码，正是「让模型把信息放对地方」的直接收益。静态 MNIST 上 NLL **79.03** 刷新当时最优（超过 PixelRNN 的 79.20）；CIFAR-10 上 DenseNet 版 VLAE 到 **2.95 bits/dim**，超过 PixelRNN 的 3.00。

**诚实边界（重要）**：论文本身**没有**语言建模实验——PTB 那个战场只出现在它的引用链里（Bowman/Chung/Serban 等序列 VAE 工作，latent 塌缩正是在那里被反复观察到）。VLAE 的分工是：给那个战场的问题一个信息论解释（3.2 节的记账）+ 一个架构解法（3.3 节的窗口）。所以「双战场」的说法要读准：**语言建模是病灶发现地，图像是疗效验证地**。

## 5. 为什么在这份 List 里

1. **批次六的压缩世界观第一次落地成可训练架构**。L21/L22 的 MDL、L25 的 Kolmogorov 复杂度讲的都是「理想中的最短描述」；这篇把 ELBO 等成码长后，压缩从解释框架变成了**设计工具**——改架构就是改码长预算的分配表。「信息偏好」原则是整份 List 里最接近「学习即压缩」操作化定义的东西
2. **它回答了前五篇理论欠下的「怎么办」**：L23/L25 讲清了压缩与智能的关系，但都是思想实验；VLAE 给出第一个可以跑、可以量、可以按比特控制的实现——「学习即压缩」从哲学变工程，就跨在这一篇上
3. **离 Ilya 最近的终站**。GPT 时代回看：预训练损失就是码长，网络学到的表征就是压缩的副产品；「模型自己决定信息放哪、想让它装什么就掐断别的路」——这条直觉后来以各种形态（条件、prompt、蒸馏）反复出现。源头账本在这篇的第 2 节

## 6. 织进网里

- **← L06 Karpathy RNN**：AR「逐 token 预测下一个」的生成观是全篇的地基；char-RNN 就是那台「强大到 z 失业」的本地建模机
- **← L21/L22 MDL 线**：ELBO=bits-back 两段码的码长，KL 项=近似过路费；MDL 的「最短描述」在这里变成可微目标函数
- **← L04 Dilated Convolutions**：视野旋钮的两极——空洞卷积免费扩视野，VLAE 故意关视野；同一参数的正反面
- **→ L25 Kolmogorov**：信息偏好原则是「最短描述赢」在梯度下降里的化身——哪个通路便宜信息走哪条，与 L25 的普适分布一脉相承
- **→ L27 超级智能**：压缩理论讲完「是什么」，这篇讲完「怎么造」，下一讲回答「这条路通向哪」
- **→ 现代生成模型**：窗口化条件生成（级联扩散用降采样图条件化）、latent diffusion「高频留给像素、语义交给 latent」的路由思想，都是这篇「信息放置」的直系后代

## 自测题

1. 强 AR 解码器为什么会让 latent 被忽略？请用码长账本（而非「优化太难」）回答。
   > 用 z 收益为零（解码器本地全能建模）而成本为正（q≠p 就要付 D_KL 过路费），最优解是 q=p、z 装零比特；论文证明即使优化精确求解，真后验不可解+解码器够强时最优解依然是忽略。
2. VLAE 的窗口化解码器在公式上长什么样？它靠什么让全局结构「只能」进 z？
   > p(x|z)=Π p(x_i|z, x_窗口(x_i))——每个像素只许看 z 加窗口内邻居；物体形状/布局在窗口外建不了，本地通路被物理掐断，全局信息只剩 z 一条路。
3. 「latent 塌缩是因为 KL 项早期太强、优化没调好」这个流行解释漏掉了什么？
   > 它把最优解当成了病：信息偏好是 VAE 的固有性质——能被解码器本地建模的信息本来就该走本地；补丁（KL annealing/free bits）只是绕路，VLAE 的答案是直接改架构分配码长预算。
4. MNIST 上 VLAE 的 z 只装 19.2 bits、factorized 版装 37.3 bits，这个对比该用 L21/L22 的什么眼光读？
   > 码长即描述长度：19 bits 说明 z 里只装得下「类别/全局形状」级的信息，窗口把局部纹理的码长全部省在了本地——两段码预算表按信息偏好自动分配，这就是 MDL 原则的工程化身。
5. 「学习即压缩」在这篇里从口号变成工程，具体跨过了哪一步？
   > ELBO 被证明等于 bits-back 两段码的码长，于是压缩不再是事后解释而是设计变量——改窗口、改条件、改 latent 层级，就是在直接编辑网络的信息路由表。
