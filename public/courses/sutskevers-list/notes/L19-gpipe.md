# L19 · GPipe — 模型大到一张卡装不下，就开流水线

《GPipe: Efficient Training of Giant Neural Networks using Pipeline Parallelism》(2018) · Yanping Huang 等(Google Brain)· [arXiv:1811.06965](https://arxiv.org/abs/1811.06965)

## 1. 一句话

GPipe 处理的问题朴素到刺眼：**模型大到单张加速器的显存装不下了怎么办?** 答案是把模型按层切成几段放上多张卡，把数据切成 micro-batch(微批次,小份的数据切片)让它们像工厂流水线一样错位流动；再用「激活重计算」拿约三分之一的算力换回数量级的显存——第一次把 63 亿参数的网络跨 TPU 训成，是大模型基建时代的第一块拼图。

## 2. 它之前的世界：显存墙

2018 年，模型的成长速度远超显存的成长速度——当时旗舰 GPU 的显存不过 16GB 量级。而显存里装的不只是参数——**激活值**(每层前向传播的中间输出,反向传播算梯度时要逐层取用)往往才是大头：batch 越大吞吐越高，激活占用同步膨胀，大 batch 下比参数本身还占地方。

当时的主流并行方案是**数据并行**：每张卡放一份完整模型副本，各吃各的数据，定期同步梯度。这个方案有个致命前提——**单卡装得下整个模型**。一旦模型大到装不下，数据并行连第一步都迈不出去。

而深度红利的方向偏偏是往深里长：ResNet 线(← L02/L03)把「更深 = 更强」证成铁律，网络的深度和宽度随军备竞赛一路膨胀。「架构上可行的深度」和「硬件上装得下的深度」正面相撞——2018 年，墙到了。

当时的应对多是委屈求全：缩小 batch 换显存、砍宽度换深度、或者干脆训不动就放弃——吞吐、规模、精度三头堵，哪头都不痛快。GPipe 的立场是：不给规模设限，让基建去追模型。

GPipe 的出发点是 Google 内部一个具体需求：用 NAS(Neural Architecture Search,自动搜索网络结构的方法)搜出来的巨型 AmoebaNet 要在 ImageNet 上继续冲纪录——模型大到任何单卡都装不下。要么放弃这个模型，要么发明新基建。他们选了后者。

## 3. 核心思想

### 3.1 流水线并行：按层切段，错位流动

思路分两步：

**第一步，切模型**。网络是层的序列，那就按层切成 K 段(比如 4 段放 4 张卡)，每段装上一张加速器——每张卡只放 1/K 的参数和激活。段与段串接：卡 1 的输出是卡 2 的输入，相邻卡之间每次只传一张边界激活张量，通信开销天然可控。

**第二步，切数据**。如果只切模型，任何时刻只有一张卡在算、其余三张干等，加速比惨不忍睹。GPipe 把每个训练 batch 切成 M 个 micro-batch(比如切成 8 份)，让它们**像流水线上的半成品一样错位进入产线**：

```
         时间 →
段1:  F1 F2 F3 F4 | B4 B3 B2 B1
段2:     F1 F2 F3 F4 | B4 B3 B2 B1
段3:        F1 F2 F3 F4 | B4 B3 B2 B1
段4:           F1 F2 F3 F4 | B4 B3 B2 B1
(F=前向,B=反向,数字=micro-batch 编号)
```

读这张图：micro-batch 1 过完段 1 进入段 2 的**同一时刻**，micro-batch 2 进段 1——四张卡同时有活干。前向全部走完后，反向按相反方向逐段流回来(梯度要往回传)。所有 micro-batch 的反向结束后，各段统一更新权重。

注意它和数据并行的区别：不是「四个人各干各的」，是**同一批产品流过一条四道工序的产线**——切的是模型，四段合起来才是完整网络。

**气泡问题**一句带过：流水线启动(填充)和收尾(排空)阶段，总有卡处于空转——图里左上和右下的三角空档，叫气泡(bubble)。气泡占比 ≈ (K−1)/(M+K−1)；K 固定时数据切得越细(M 越大)，气泡越可忽略。代价是 micro-batch 变小、单次计算效率下降，M 的取值是两者权衡。

### 3.2 显存账：切了模型，激活还在

切段直接把参数切成 1/K——但显存大头不止参数。前向传播每层的中间激活都得存着，等反向传播回来取用：K 张卡各存各的激活，batch 越大存得越多。摊开账目：每张卡的激活 ≈ 段内层数 × micro-batch 尺寸 × 层宽——切段省下了参数，省不掉正在产线上流动的激活。模型切了，**激活的显存墙还在**。拆掉这堵墙的招，才是 GPipe 的招牌技术。

### 3.3 激活重计算：拿算力换显存

激活重计算(activation checkpointing,前向不存中间激活、反向时重算恢复的「显存换算力」技巧)的做法：

- 前向时，只在**段边界**存激活(检查点)，段内部的激活算完就扔
- 反向传播走到某一段时，先从段边界的检查点**把这段的前向重算一遍**，恢复内部激活，再照常算梯度

代价明码标价：每段多做一次前向，总计算量从 F+B 变成 F+B+F，论文报告约 **+33%**。换来的是段内部激活的显存占用几乎归零——用算力(可再生的、可堆的)换显存(硬墙、切不开的)，这笔交易在 scale 信仰下的方向天然确定。

**为什么敢重算?** 两个前提缺一不可：

1. **前向是纯函数**：同样的权重 + 同样的输入，重算结果逐比特一致。GPipe 的调度保证所有 micro-batch 的前向和反向全部完成后才统一更新权重——反向途中权重纹丝不动，重算路径完全确定
2. **计算图干净**：网络的主体是规整的残差堆叠(← L02/L03)。identity 捷径上不挂任何变换、不藏任何状态，每层就是「直通 + 一个可重算的变换」的组合——整张计算图没有旁路、没有隐状态，**「重算一遍 = 原样复现」在架构上是可靠约定**

这里正是 L03 价值观在系统层的回响：Identity Mappings 那篇证明，**干净通路(捷径上不加任何变换)让信号和梯度毫无损耗地直达深层**；GPipe 说，同一份「通路干净」的红利，一次付给了训练动态(梯度好流)，一次付给了系统基建(状态敢扔、敢重算)。残差通路干净，重计算才站得住。

类比：版本管理里不存每个文件每个版本的完整快照、只存关键检查点 + 变更序列，要旧版本时从最近的检查点重放——前提只有一个：重放过程确定性可复现。

这个技巧后来被做进主流框架的标准 API(如 PyTorch 的 checkpoint)，成为此后一切巨型训练的默认开关：开，就用算力买显存；不开，显存墙立在那里。

### 3.4 大 batch 的副作用(一句带过)

M 个 micro-batch 合起来是数万样本的超大 batch，而超大 batch 会让 BatchNorm 的统计失真、训练失稳。GPipe 的配套解法：学习率随 batch 尺寸线性放大 + 前几个 epoch 用小学习率预热(warmup)，把大 batch 训稳。

## 4. 实验逻辑

- **战场一(ImageNet,刷纪录)**：6.55 亿参数的 AmoebaNet-B——单卡装不下、流水线并行训成，论文报告刷新当时 ImageNet 纪录(top-1 约 84%)。同配置但单卡装得下的较小模型做对照：证明大规模本身在涨点
- **战场二(规模演示)**：63 亿(6.3B)参数的巨型网络跨大量 TPU core 训成。这一仗不看精度，看「能训」——单卡时代不可想象的模型规模，基建使能后成为现实。顺带一个刻度：2018 年的「巨型」是 6.3B，两年后 GPT-3 把刻度画到 175B——基建每抬一寸，「巨型」的门槛就重画一次
- **账目三件**：
  - 气泡：实测随 M 增大而衰减，与公式吻合
  - 重计算：激活显存大幅下降(与段内层数成比例)，代价约 +33% 计算，论文报告净收益为正
  - 组合：流水线并行可与数据并行嵌套(再复制几条产线)，两种并行正交叠加，总规模 = 段数 × 产线副本数

## 5. 为什么在这份 List 里

1. **「大模型基建元年」的样本**。此后训练巨型模型的并行三分天下——数据并行(切数据)、流水线并行(切层)、模型并行(切张量)——GPipe 是流水线那块的第一块拼图。论文验证用的还是卷积网，但「按层切段」的切法对任何层叠结构成立，Transformer 时代的巨型训练全部继承这套流水线。没有这类基建，L20 的 Scaling Laws 只是纸面价目表：算得清「买多少算力换多少能力」，却没有机器能把模型训起来
2. **「拿算力换显存」的价值观样本**：当 scale 是信仰，算力是可再生的，显存是硬墙——+33% 算力换数量级显存，交易方向天然确定。「用富余资源换稀缺资源」的工程直觉，贯穿此后所有大模型基建
3. **「架构不动，基建使能」**：网络结构一行没改，可训的模型规模被基建硬生生抬上一个数量级——Ilya 世界观三角里算力支柱的工程兑现

## 6. 织进网里

- **← L18 Deep Speech 2**：scale 信念的两条腿——L18 证「喂得起数据」，本篇证「装得下模型」；工程学前传的两块拼图

## 自测题

1. 数据并行的致命前提是什么?GPipe 的两步走是什么?
   > 数据并行要求每卡装下完整模型副本，模型超显存即失效；GPipe 先按层把模型切 K 段放上 K 张卡(流水线并行)，再把 batch 切成 M 个 micro-batch 错位流入产线，让各段同时开工。
2. 气泡是怎么产生的?占比公式是什么?怎么压到可忽略?
   > 流水线填充/排空阶段部分卡空转(F/B 图上的三角空档)；占比 ≈ (K−1)/(M+K−1)；K 固定时把 batch 切得更细(M 越大)气泡越可忽略，代价是 micro-batch 过小降低单次计算效率，需权衡。
3. 激活重计算的做法和代价是什么?它为什么敢重算?
   > 前向只在段边界存检查点、段内激活全扔，反向走到该段先重算前向恢复激活再算梯度；代价是多一遍前向、总计算量约 +33%；敢重算因为前向是纯函数(反向前权重不动、重算逐比特一致)且残差计算图干净无旁路状态——重算 = 原样复现。
4. 易混淆：流水线并行和数据并行差在哪?
   > 数据并行切数据：每卡完整模型副本、各吃各数据、只同步梯度；流水线并行切模型：每卡一段、同一批 micro-batch 依序流过整条产线(前向逐段推进、反向逐段回流)，四卡合起来才是一个网络——「工厂流水线，不是四个人各干各的」。
5. GPipe 在 Ilya「模型×数据×算力」三角里扮演什么角色?和 L03 的勾连点在哪?
   > 算力支柱的工程兑现：单卡装不下时，把「算力可扩展」从口号变成流水线+重计算的可行工程，是通往 L20 规模时代的第一块基建拼图；与 L03 共享「干净通路」价值观——梯度好流(训练动态)与状态敢扔(系统基建)是同一份红利的两次兑现。
