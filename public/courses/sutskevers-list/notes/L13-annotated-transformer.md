# L13 · The Annotated Transformer — 把论文逐行翻译成能跑的代码

《The Annotated Transformer》（初版 2018，哈佛 NLP 网页文档，此后多次更新） · Sasha Rush 等 · [nlp.seas.harvard.edu/annotated-transformer](https://nlp.seas.harvard.edu/annotated-transformer/)

注意：这篇不是论文，也不提出任何新方法——它是 L12《Attention Is All You Need》的逐行 PyTorch 复现：论文的每一段、每一张图、每一个公式，后面紧跟一段可复制运行的真实代码。一份教学文档被选进以论文为主的 List，本身就是一次表态：读懂一张蓝图，和能把房子盖出来，是两种能力。

## 1. 一句话

它只做一件事：**把 L12 从头到尾翻译成逐行可运行的代码——每个公式落成函数、每个模块落成类、每句「训练细节」落成具体的数与操作**，从而填掉「读懂论文」和「能写出代码」之间那道人人默认存在、却很少有人正面处理的断层。

## 2. 它之前的世界：读懂了，但写不出来

2017 年 6 月 Transformer 论文放出后迅速成为现象。但如果你在 2018 年初想「自己实现一遍」，会发现两边都不对劲。

论文这边，它为发表而生。发表体系激励的是「讲清思想、证明有效」，不是「给够实现细节」。于是实现者最需要的东西——张量到底几维、mask 加在 softmax 之前还是之后、8 个头怎么从 512 维里切出来、初始化用什么——在论文里统统被压缩成一行公式或一个符号。**论文省略的，恰好是实现者最先撞上的**。

代码这边，Google 官方的 `tensor2tensor` 实现是公开的，但它嵌在一套庞大的研究框架里：多层抽象、配置系统、为实验规模服务的工程优化。想从里面读出「Transformer 到底是哪几行」，你得先学会整套框架，再自己做减法。论文是提纲挈领的地图，官方代码是塞满家具的仓库——中间缺一本逐句对照的说明书。

这个缺口不是 Transformer 特有的，是整个领域的通病。你以为缺的是「一篇更详细的论文」，其实缺的是一种**文体**：让代码按「人类理解的顺序」而不是「工程组织的顺序」排列。这个顺序观有个古老的渊源——Knuth 在 1980 年代提出的「文学编程」（literate programming）：代码不必按执行路径组织，而按读者理解的路径组织，解释与代码交织成可读的文档。哈佛 NLP 的 Sasha Rush 等人把这个传统搬到了深度学习论文上，做成一篇网页文档：论文段落（引用块）→ 对应实现（代码块）→ 点睛注解，按论文叙事顺序串起来，而且每段代码真的能跑。

## 3. 核心思想：一张「论文 → 代码」的翻译表

### 3.1 「annotated」这个文体为什么值一个席位

读论文时你自以为懂了：Q 乘 K 转置、过 softmax、乘 V——这不就是三行矩阵乘法？真正动手时，问题换了一种问法：query 和 key 各是什么形状？`QKᵀ` 出来是几维？softmax 沿哪个维度归一？多头是循环 8 次还是一次 reshape？测试时 decoder 怎么从「输出一个词」变成「输出一句话」？

**这些问题论文一个都不会回答，但在写代码时每个都必须给出答案**。断层就在这里：论文检验的是「你能否复述逻辑」，代码检验的是「你能否做出所有隐藏决策」。annotated 文体的价值不在讲解（讲解类内容 L05/L07 已经是样板），而在**强制把每个隐藏决策显式化**——任何一个含糊处，代码都编译不过或跑出错误结果，没有含糊的余地。读懂是理解了「是什么」；写出是回答了「每个符号在内存里长什么样」。后者才是能就业、能改架构、能做研究的理解。

### 3.2 翻译表：公式落成函数，模块落成类

整篇教程可以压缩成一张翻译表——论文的每个元素在代码里都有一个唯一落点：

```
论文里的元素                        代码里的落点
──────────────────────────────────────────────────────
Attention(Q,K,V) 公式         →   attention() 函数（核心就几行）
「8 个头并行」一段话          →   MultiHeadedAttention 类
编码器一层的结构图            →   EncoderLayer 类
「N=6 层堆叠」                →   Encoder / Decoder 容器类
整张架构图（Figure 1）        →   EncoderDecoder 类的 forward()
正弦位置编码公式              →   PositionalEncoding 类
「we use label smoothing 0.1」→   LabelSmoothing 损失类
「warmup 4000 steps」一句     →   NoamOpt 学习率调度类
训练循环（半页文字）          →   Batch 类 + run_epoch 函数
```

这张表的规律很清楚：**公式最便宜，图的代价居中，文字训练细节最贵**——越是被一句话带过的地方，翻译成本越高。以多头注意力为例：论文里「8 个头」是一句话，实现里最非平凡的一步是切头——把 `n×512` 的张量 `view` 成 `n×8×64` 再转置维度。这里没有任何「并行」，只有 reshape 和 transpose；切错一维，输出形状对了、语义全错，而且不报错。「论文以为你知道、编译器知道你不知道」的细节，正是这张翻译表的真正价值所在。

### 3.3 两个「露馅」现场：读原文以为懂了，写代码全露馅

**露馅一：因果掩码是「加 −1e9」，不是「乘 0」。** 论文公式写 `softmax(QKᵀ/√d_k + M)`，M 是一个抽象符号，配文一句「mask 掉非法连接」。实现时三个问题接踵而至：

- **加在哪？** 必须加在 softmax 之前的打分上。softmax 之后才处理就来不及了——归一化分母已经把「偷看的未来」计入了
- **加什么？** 加一个大负数（`-1e9`），**不是 0**。把未来位置的分数置 0，softmax 后它仍分到不小的权重（分数为 0 不等于概率为 0）；置 −1e9，softmax 后才真正趋近 0。为什么不用 −∞？全 −∞ 行会让 exp 下溢出 NaN——`-1e9` 是工程上的数值稳定性折中
- **什么形状？** 下三角因果掩码与 padding 掩码合并，靠广播对齐 `batch × 头 × 序列 × 序列` 四维

最终落进代码就是一行 `scores = scores.masked_fill(mask == 0, -1e9)`——但支撑这行的是三个决策。写错任何一个位置或任何一个数，模型不报错，只是偷偷「看了答案」或 NaN 崩溃。没有逐行实现，你根本不知道论文那一行公式里藏着三道岔路。

**露馅二：label smoothing 改变了「什么是好模型」的定义。** 论文训练细节里一句「label smoothing ε=0.1」，实现时它变成一个完整的损失类：把 one-hot 真值（正确类 1、其余 0）换成「正确类 0.9 + 均匀分布 0.1」，用 KL 散度算损失。然后一个反直觉的现象浮出水面：**平滑之后训练困惑度（perplexity，语言模型每步平均在多少个等效候选词里犹豫）变得更差**——因为模型被刻意教得更「不确定」；**但翻译质量（BLEU）和准确率反而上升**。论文自己都特意注明「这伤害困惑度，但改善准确率与 BLEU」。不亲手实现，这句多半被当成脚注滑过去；亲手实现过才明白它的分量：**训练损失这个度量已经被技巧扭曲了——从此不能拿训练 loss 直接比较两个模型的好坏**。这是「实现级理解」的教科书案例：读时是无关紧要的超参，写时才发现它重写了评价标准。

顺带第三个常被追问的细节：LayerNorm 摆哪。论文是「子层之后归一」（post-LN），后来的实现普遍挪到「子层之前」（pre-LN）才让深栈训练更稳（→ L12 已展开）。「归一化摆前还是摆后」这种纯实现的位置问题，同样只有落码时才被迫回答——而答案影响深栈能不能训得动。

## 4. 文章怎么展开论证

教程类文本，论证方式与论文不同——它的说服力来自「你随时可以亲手验证」：

- **单元结构三件套**：每个单元先放论文原文（引用块，忠实转录），紧跟对应的实现代码，再配一两句注解。读者永远同时拿着「宣称」和「落地」两份材料，宣称含糊处代码立刻现形
- **顺序忠于论文**：背景 → 顶层 `EncoderDecoder`（对应架构总图）→ 逐层下钻 `Encoder`/`Decoder` → `EncoderLayer`/`DecoderLayer` → `attention`/`MultiHeadedAttention` → `PositionalEncoding` → 完整模型 → 训练配套（`Batch`、label smoothing、Noam 调度）→ 解码。阅读顺序＝理解顺序＝（近似）依赖顺序——这正是文学编程的核心主张
- **先玩具后真实**：先用一个玩具任务（让模型学会复制一段序列）把「建模型→训练→解码」全流程跑通，肉眼可验输入输出；再给出在 WMT 2014 真实翻译数据上多 GPU 训练的完整代码，复现出与论文同量级的 BLEU。论文的宣称从「Google 说它有效」变成「你可以自己跑一遍看它有效」
- **诚实边界**：教程不改架构、不发明新东西，实现忠实原文（post-LN 等）；性能优化、分布式训练放附录。它的野心不是改进，是**零损耗翻译**

## 5. 为什么在这份 List 里

1. **「实现级理解」的方法论示范**。L03 是作者回头解剖自己提出的模块，把「哪些细节其实无所谓」找出来；本篇反过来，是教学者逐行解剖别人的论文，把「哪些细节其实要命」挖出来——同一件事的两个方向。真正的理解发生在把符号落实成张量形状的那一刻。这份 List 的主体是「相信规模」，本篇补上的是相信的手艺：能自己跑一遍，才谈得上判断
2. **GPT 时代的传播枢纽**。2018 年正是 GPT-1 发布之年；此后几年，「读懂 Transformer」的默认入口就是这篇。无数从工程侧转入 NLP 的工程师从这里进门——scaling 叙事（→ L20）需要的不只是论文，还需要能把论文变成公共知识的基础设施
3. **annotated 文体的可复制性**。它示范了一种格式：原文引用 + 可运行代码 + 点睛注解，此后大量「The Annotated X」式效仿出现，成为深度学习教学的一个小流派——「复现」从个人苦役变成社区模板。这符合这份 List 的一贯趣味：一种让能力变便宜的「聪明排列」，胜过一次昂贵的单点努力

## 自测题

1. 「读懂论文」和「能写出代码」之间的断层是什么？annotated 文体靠什么动作填掉它？
   > 论文检验「能否复述逻辑」，代码检验「能否做出所有隐藏决策」（张量形状、mask 位置、切头方式、初始化——发表体系激励省略它们）；annotated 的动作是强制显式化：每个含糊处代码要么编译不过要么跑错，没有含糊余地。
2. 因果掩码实现要回答哪三个问题？把未来位置分数「置 0」错在哪？
   > 加在哪（softmax 之前的打分上，之后则归一化分母已计入偷看项）、加什么（大负数 −1e9 而非 0——分数 0 经 softmax 仍分到权重，−1e9 才让权重≈0，也不用 −∞ 防下溢 NaN）、什么形状（下三角因果掩码+padding 掩码合并、广播对齐四维）。
3. label smoothing 让 perplexity 变差、BLEU 反而变好——这个反直觉现象教会实现者什么？
   > 训练损失这个度量被技巧扭曲了：模型被教得更「不确定」（每步犹豫的候选词更多）所以困惑度虚高，但这种不确定带来更好泛化——教训是不能拿训练 loss 直接比较模型好坏；读论文它是脚注，写代码它重写了「什么是好模型」的定义。
4. 本篇与 L03、L07 各是什么关系？三种文本在「理解」这件事上如何分工？
   > L03 是作者解剖自己的模块（找「哪些细节无所谓」），本篇是教学者解剖别人的论文（挖「哪些细节要命」）——实现级理解的两个方向；L07 是讲解端样板（先直觉后式子），本篇是实现端样板（先原文后代码）——传播的两端。
5. 一份不提出新方法的教学文档为什么值一个 List 席位？它对 scaling 叙事的贡献是什么？
   > 它是「实现级理解」的方法论示范与知识基础设施：把论文变成人人可自验的公共知识（复现从个人苦役变社区模板），2018 年起成为工程师读懂 Transformer 的默认入口——scaling 叙事的行业共识，靠的正是「人人能跑一遍」的工程师文化。
