Ashok Elluswamy（Tesla AI 副总裁）在 ICCV 2025 WDFM-AD 研讨会（2nd Workshop on Distillation of Foundation Models for Autonomous Driving，檀香山）发表主题演讲「Building an Autonomous Future」，远程出席。这是 Tesla 首次对外结构化拆解其端到端基础模型技术栈。本文基于演讲字幕全文逐段精读整理，并与研讨会主办方发布的官方博客交叉验证——文中演讲者的宣称均已标注口径，未经 Tesla 官方确认的数字单独说明。

## 1. 一句话

Tesla 首次公开拆解：FSD（Full Self-Driving，完全自动驾驶）与 Robotaxi 由**一个大型端到端神经网络**驱动——摄像头像素直接进、控制动作直接出，中间没有人工设计的模块边界；而 Ashok 认为**评估（evaluation）才是最难的一环**，解法是自研神经网络世界模拟器，把评估搬进可交互的生成式环境里。

## 2. 成绩单：2025 年的 Robotaxi 走到哪了

演讲开篇给了三个「已经发生」的事实（均为演讲者陈述）：

| 事实 | 细节 |
|---|---|
| Robotaxi 服务上线 | 6-7 月在 Austin 与旧金山湾区运营；Austin 场景 40 mph（约 64 km/h）以下车内无安全员 |
| 工厂直送交付 | 第一辆客户车从 Austin 工厂自动驾驶到客户家，全程 20-30 分钟，覆盖高速、城市道路、停车场 |
| 全系自运 | 美国出厂的每辆 Tesla 都自己从产线开到几英里外的装卸码头 |

他强调直送用的是**量产车、量产摄像头、与所有在售车相同的计算机**——不是特改装车。这套演示的潜台词：自动驾驶已经不是实验室能力，而是产线日常。

## 3. 为什么 all-in 端到端

技术栈核心：**单一大型端到端神经网络**，输入原始像素 + 导航地图 + 车辆运动学 + 音频，输出控制动作（「Photon In → Control Out」，光子进、控制出——主办方博客的说法）。演讲明确：模型**不再做显式的车辆检测、道路边界感知**，这些可以隐式存在，也可以作为辅助任务训练，但驱动车辆的就是从视频流到动作的直通映射。

为什么放弃传统的模块化方案（perception 感知 → prediction 预测 → planning 规划，分开优化再拼接）？他给了三个理由：

**理由一：人类偏好无法显式编码。** 遇到障碍物是急刹还是缓刹？刹车太早体验差、太晚不安全，且低速与高速的合理阈值完全不同——这不是一个有客观最优解的工程参数，而是把人类价值观对齐到代码的问题。「你可以试着重写它，但写不好。」

<details class="mt-3 mb-4 rounded-xl border border-slate-200 bg-slate-50 px-4 py-3 text-sm">
<summary><strong>展开论证｜为什么「刹车时机」能推翻模块化</strong></summary>
<ul>
<li>模块化方案的隐含假设：每个驾驶决策存在可写的显式代价函数（cost function，给每个候选动作打分的数学函数）。</li>
<li>Ashok 的反例：同一障碍物，合理策略是「尽快逼近再晚刹」还是「提前缓刹」，取决于速度、路况、乘客舒适度偏好。</li>
<li>这意味着代价函数不是一条曲线，而是随场景连续变化的偏好分布——用代码枚举这些规则等于无穷尽的打补丁。</li>
<li>而神经网络从人类驾驶数据里学的正是这个偏好分布本身，不需要人工把它显式化。</li>
<li><strong>一句话：</strong>难写的不是「怎么开车」，是「人类觉得怎样算开得好」——这恰恰是学习方法的主场。</li>
</ul>
</details>

**理由二：模块接口有损。** 传统感知输出物体列表（bounding box 边界框、语义地图），这个接口「ill-defined（定义不良）」且丢信息——罕见场景（如动物过马路）在物体列表里根本无法恰当表达，不确定性也无法贯穿全系统传播。

**理由三：确定性延迟。** 模块化分支计算的延迟不确定且不可预测，而实时系统要求确定性的延迟。单一网络提供这种保证。

三个现场视频例子（都是自驱状态）：

- 双向单车道积水，借对向车道绕行——「闯对向的代价 vs 涉水的代价」没有显式代码可写，但看一眼场景就知道该绕；
- 鸡群过马路，等最后一只过完才走（「没有碰撞风险，但这就是该做的事」）；
- 鹅群站在路中不动，模型判断它们**不是在过马路而是停着**，于是倒车、转向绕行——现场观众惊呼「It's changing its mind」（它改变主意了）。

## 4. 难点一：维度灾难——20 亿 token 进，2 token 出

Ashok 说开发这样的系统「非常难」，第一个难点是 curse of dimensionality（维度灾难：输入空间维度极大而输出极小，学习正确映射异常困难）：

- 每车 **7-8 个摄像头**（依车型），每个 5MP（百万像素）、高帧率（主办方博客称 36 Hz，演讲正文只说「high frame rate」）；
- 30 秒上下文窗口 + 路线 + 车速等运动学数据，输入规模「轻松超过 **20 亿 token**」；
- 输出只有**约 2 个 token**：下一时刻的转向与加速度。

<details class="mt-3 mb-4 rounded-xl border border-slate-200 bg-slate-50 px-4 py-3 text-sm">
<summary><strong>展开论证｜multi-to-one 映射难在哪</strong></summary>
<ul>
<li>语言模型的映射是「多 token 进、多 token 出」，输入输出同量级；驾驶是「20 亿进、2 出」的极端压缩。</li>
<li>天真地堆一个巨型 transformer（变换器网络）做暴力映射，模型会抓到大量 spurious correlations（虚假相关：与真实因果无关的统计巧合）——比如「这段路面通常伴随这种微操」，换个分布就崩。</li>
<li>真正要学的是那 2 个 token <strong>为什么</strong>是对的：从压倒性上下文里提取「正确的信号」并跨分布稳健泛化。</li>
<li>这是数据问题而非架构问题——所以解法是下一节的数据引擎。</li>
</ul>
</details>

Tesla 的应对是数据引擎（data engine：从车队海量行驶记录中筛选、定向采集高价值训练数据的系统）：50 万年量级的驾驶数据（原文「500 years of driving」）远超集群存储能力，必须提炼出「覆盖驾驶谱系的精华数据」。三种提炼手段（演讲原话归纳）：

1. **显式触发器**——命中预设场景条件时自动留存片段；
2. **小型专用神经网络**——针对特定场景定向挖掘；
3. **预测-实际偏差监控**——持续比对模型预测与真实发生的情况，偏差即高价值样本。

他特别强调这类罕见数据**无法摆拍**：「它需要静止的场景、场景里所有车辆的状态空间，这真的很难人为达成」——只有全车队规模才能白捡。这是 Tesla 相对竞争对手的护城河（他称之为「Niagara Falls of data」，数据的尼亚加拉瀑布）。

## 5. 难点二：黑箱怎么调试——同一模型的「第二职业」

「它是端到端的，那坏了你怎么调试？」——他的回答：**同一个模型可以被 prompt（提示词）着去预测任意中间产物**：3D occupancy（占用栅格：把 3D 空间切成小格子、标注每格是否被物体占用的表示）、红绿灯、路沿、物体类别，甚至**用自然语言解释自己的决策**。要点是：车端实时行驶只消费控制动作，其余输出都是辅助——但它们提供可解释性与内部监督信号，反过来帮助模型学出更正确的控制。

### 5.1 Gaussian Splatting 变体

Gaussian splatting（高斯泼溅：用数万个带颜色与透明度的椭球「泼」出 3D 场景、可实时渲染的 3D 重建技术）是近年学界热点，但传统管线（nerfstudio 等工具）在驾驶场景有个死穴：车辆基本直线前进、相机基线（视角差异幅度）极小，训练视角附近渲染很美，**偏离训练分布的新视角就崩**——模糊、糊成一片。还需要 COLMAP（从多视角照片反推相机位姿的传统工具）等显式求解器做初始化、耗时几十分钟。

Tesla 的变体由**同一个基础模型直接生成 Gaussians**：

| 维度 | 传统 splatting | Tesla 变体（演讲演示） |
|---|---|---|
| 非训练视角泛化 | 崩、模糊 | 旋转查看时 3D 结构大体完整 |
| 位姿初始化 | 需要 COLMAP 类求解器 | 不依赖传统初始化 |
| 速度 | 几十分钟 | 「ridiculously fast」，可快速更新场景 |
| 语义 | 无 | 第三列直接输出语义 |

用途：调试。可视化车辆是在加速还是减速、是否安全避开障碍——工程师可以钻进模型「看到」的场景里。

### 5.2 一个模型，两种工作节奏

- **fast path（快速通道）**：正常行驶，直接吐控制动作，无推理开销；
- **reflective mode（反思模式）**：时间充裕时先产出 reasoning tokens（推理 token：模型先写显式思考链再给答案的中间 token），让动作与推理一致。

<details class="mt-3 mb-4 rounded-xl border border-slate-200 bg-slate-50 px-4 py-3 text-sm">
<summary><strong>展开论证｜为什么不全程深想</strong></summary>
<ul>
<li>每个决策都走完整推理链，延迟会被推理长度吃掉——实时控制等不起。</li>
<li>所以默认走 fast path：直觉式直出动作（对应心理学 System 1 快速直觉）。</li>
<li>只在「需要」的场景触发反思：先想清楚再出动作，且保证动作与推理一致（对应 System 2 慢速推理）。</li>
<li>这是「test-time compute（测试时计算量：推理阶段愿意花多少算力）按需伸缩」的驾驶版：把算力花在难的地方。</li>
<li><strong>一句话：</strong>同一权重、两种节奏，难例深想、常态直出。</li>
</ul>
</details>

## 6. 难点三：评估才是最难的一环

Ashok 原话：评估「是这三个问题里**最难的**」（三个问题指维度灾难、可解释性、评估）。开场白很直接：把海量司机数据喂进去训练、不断扩规模，**开环（open-loop：模型输出与既定剧本比对、输出不回灌影响下一步）指标看起来很漂亮，但不一定能转化成真车实际驾驶表现**。他没展开具体机制（「原因很多，不细讲」），只强调这需要大量投入。

评估还有第二个坑：**评估集本身**。随机抽车队数据，绝大多数是无聊的高速巡航——在这样的分布上评估没有意义。解法还是数据引擎：用同一套触发器/挖掘机制构造**均衡且全覆盖的评估集**。他坦承这活「极其重要但非常枯燥（tedious）」。

一个演示细节值得展开（proactive safety，主动安全的二阶推理）：

<details class="mt-3 mb-4 rounded-xl border border-slate-200 bg-slate-50 px-4 py-3 text-sm">
<summary><strong>展开论证｜前车失控时，为什么「早刹车」是智能的标志</strong></summary>
<ul>
<li>演示场景：高速上前方一辆车失控打转、即将撞护栏并弹回本车道；Tesla 在前车<strong>尚未撞击</strong>时就开始约 4 m/s² 的制动（「这不算轻的制动」）。</li>
<li>关键：此刻证据链尚未闭合——失控车还没有弹回来，它的轨迹变化也可以被解释成「它要变道」。</li>
<li>普通系统要等一阶事件发生（撞了、弹回来了、速度向量变了）才反应；Tesla 模型在打转阶段就预判了二阶后果（撞护栏 → 反弹 → 侵入本车道），提前制动。</li>
<li>Ashok 的判据很硬：4 m/s² 的减速度请求只可能来自「预判碰撞即将发生」，不可能是误判变道——所以模型不是碰运气，是真理解了物理。</li>
<li><strong>一句话：</strong>智能的度量不是反应多快，是<strong>在坏事发生之前多早就知道它要发生</strong>。</li>
</ul>
</details>

## 7. 世界模拟器：把评估搬进神经网络

这是全场技术含量最高的部分。核心洞察一句话：**把「状态-动作对」反过来用，就能免费训练一个世界模型**。

### 7.1 训练原理

state-action pairs（状态-动作对：某时刻的环境快照 + 当时执行的动作）是驾驶数据里**免费且廉价**的东西——不需要人工标注、不需要最优驾驶。训练目标反转：**给定过去状态 + 动作，预测下一状态**。任何「trash driving（垃圾驾驶）」都能当训练数据，因为模拟器需要的恰恰是各种边缘情况。

<details class="mt-3 mb-4 rounded-xl border border-slate-200 bg-slate-50 px-4 py-3 text-sm">
<summary><strong>展开论证｜为什么 state-action 反转就能学出世界模型</strong></summary>
<ul>
<li>正常驾驶模型学的是「状态 → 最优动作」；世界模拟器学的是「状态 + 任意动作 → 世界的下一帧」。</li>
<li>第二个问题的监督信号无处不在：车队每一秒都在产生「此刻状态 + 司机做的动作 + 接下来世界真实的样子」三元组，全部是免费标签。</li>
<li>学成之后，把「下一状态」再喂回去、接上任意动作，就能无限滚动生成（autoregressive，自回归：输出逐段接回输入）。</li>
<li>它天然覆盖边缘情况——因为车队数据里本来就有大量人类的离谱操作。</li>
<li><strong>一句话：</strong>不用造标注、不用造场景，物理规律本身藏在每一帧「动作 → 后果」里。</li>
</ul>
</details>

### 7.2 演示规格

- **单网络同时生成 8 路相机视频**（前排、左右侧、后视各若干），每路 5MP；
- **动作条件化**（action-conditioned：生成结果随输入动作变化）——可以实时「驾驶」这个模拟器，转向、刹车都响应；
- 一次连续生成 1-1.5 分钟、8 路 5MP 全程一致；跨相机一致性到「轮圈、红绿灯」级别；
- 降低 test-time compute 可达**近实时渲染**，演示了 6 分钟连续可交互驾驶，甚至故意开上路缘（curb）测试泛化，画面依然稳定。

### 7.3 三种评估用法

| 用法 | 做法 | 价值 |
|---|---|---|
| 旧 issue 重放 | 一年前的失效案例（如离行人过近）直接喂给最新网络重跑 | 不用等新里程积累，立刻验证「这个问题修没修好」 |
| 对抗注入 | 原视频中直行的车条件化改为切入本车路径，其余场景保持一致 | 合成 corner case 评估集：改一个变量、控制其余变量 |
| 闭环强化学习 | 让策略在模拟器里连续驾驶，长时间验证不碰撞 | closed-loop RL（强化学习，用奖励信号训练策略的方法）的训练环境 |

第三行是真正的想象空间：Ashok 点明这工具「不仅用于评估，也可用于闭环强化学习」。模拟器即训练场。

## 8. 展望：同一套栈，从车到人形机器人

结尾部分的三个宣称（均为演讲者口径）：

1. **Robotaxi 扩张**：目标解锁全车队完全自动驾驶；Cybercab（Tesla 下一代专用车型）只有两个座椅、为 robotaxi 而生，宣称「交通运输成本将是最低的，甚至低于公共交通」；
2. **方法可扩展**：同一方法跨车型平台、跨地域、跨天气 conditions 都成立；
3. **迁移到 Optimus**（Tesla 人形机器人）：世界模拟器的视频生成对 Optimus 同样工作——演示了 Optimus 在工厂中导航的**全生成视频**；且支持动作条件化：原始片段直行为 ground truth（真值参照），条件化后可正确生成左转、右转等不同动作下的像素。「同一个神经网络，加入一些 Optimus 数据，就能泛化到其他机器人形态。」

收尾口号：「Tesla is all in on robotics」——全公司聚焦造「智能、有用、大规模」的机器人，随后是招聘话术（对 AI/机器人/视觉研究者喊话）。

## 9. 金句

> 「It requires a lot of intelligence to understand that something is going wrong way before it actually goes wrong.」——在坏事发生之前很久就意识到它要发生，这才叫智能。（Ashok 谈前车失控预防性制动）

> 「Basically has access to the Niagara Falls of data, and it's up to Tesla to use this data to solve this problem.」——车队数据是尼亚加拉瀑布，关键看你会不会接。（Ashok 谈数据优势）

> 「You can't stage this that easily... Tesla has a unique advantage here that it can tap into the entire fleet to get this data.」——罕见场景摆不出来，只有全车队白捡。（Ashok 谈数据引擎）

> 「Any kind of trash driving is good enough for this kind of simulator.」——垃圾驾驶也能训练世界模拟器。（Ashok 谈 state-action 反转训练）

> 「Evaluation... is actually the most difficult of these three problems.」——评估是三个问题里最难的。（Ashok 的自我排序：维度灾难 < 可解释性 < 评估）

> 「Tesla is all in on robotics. The entire company is just focused on producing intelligent, useful, large-scale robots.」——（Ashok 结尾宣言）

## 10. 我的判读

**可迁移的洞察：**

- **端到端辩护 = LLM 范式迁移**。Ashok 三条理由里最硬的一条是「人类偏好难显式编码」——这与 RLHF（基于人类反馈的强化学习）存在的理由是同一件事：与其手写规则，不如从人类行为分布里学偏好。自动驾驶的今天就是语言模型的昨天，模块化 → 端到端的迁移剧本完全同构。
- **「20 亿进 2 出」是约束不是缺陷**。动作空间极小反而逼出了正确的工程方向：既然输出没法靠「生成多个候选挑一个」，唯一杠杆就是输入侧的数据质量与训练侧的评估闭环。这与 LLM 靠采样多样性绕错的路完全不同，值得记在「问题形态决定方法论」这一类。
- **评估瓶颈论与行业共振**。「loss 不预测真实表现、开环假指标」在 agent 开发里一比一复现——benchmark 分数不预测真实任务成功率。Tesla 的答案是自造可交互环境（世界模拟器）；对任何 agent 项目的启示：**先造环境，再谈能力**。世界模拟器的 state-action 反转训练经济学（本来就要发生的事当免费标签）是范式级技巧，任何「有历史行为日志 + 最终结果」的领域都能抄。
- **「难例深想、常态直出」的双模式**就是 reasoning model 的 adaptive thinking 在实时系统的落地形态——按需分配 test-time compute，这在实时产品里是通用架构模式。

**阅读姿势（打折扣的部分）：**

- 约 trillion 参数、36 Hz 两个数字出自**主办方博客转述**，未经 Tesla 官方确认（博客作者为研讨会组织方，非 Tesla 员工）；
- 「transfers most seamlessly to other forms of robots」是宣传口径，演示只有视频生成、没有真实机器人控制结果；
- 全部行驶数据与 demo 出自演讲者本人，无第三方核验；「40 mph 以下车内无人」为运营限定条件，不等于全域能力；
- 招聘话术（「best place to work on AI」）与结尾宣言是公司叙事，听个方向就好。

**值得盯的先行指标：**

- Cybercab 量产与无安全员速度上限（40 mph）的提升节奏；
- 世界模拟器是否发论文/开源（WDFM-AD 系列研讨会有 Waymo 讲 distillation 的先例，学界互动是真需求）；
- 同一演讲者后续 keynote 的增量（其 CVPR'26 keynote 已在 YouTube 流传，66K 播放）；
- 对抗注入评估是否成为行业标配——它直接决定「罕见场景验证」的成本曲线。

## 11. 术语速查

| 术语 | 白话解释 |
|---|---|
| FSD（Full Self-Driving） | Tesla 完全自动驾驶系统，量产辅助驾驶的旗舰形态 |
| Robotaxi | Tesla 的无人驾驶出租车服务，2025 年 6-7 月在 Austin 等地运营 |
| Cybercab | Tesla 下一代专用 robotaxi 车型，双座、无方向盘设计定位 |
| Optimus | Tesla 的人形机器人 |
| End-to-end（端到端） | 传感器原始数据直接进单个网络、网络直接吐控制动作，中间不设人工模块边界 |
| Modular pipeline（模块化管线） | 感知 → 预测 → 规划各模块分开优化再拼接的传统自动驾驶架构 |
| Cost function（代价函数） | 给每个候选动作打分的数学函数，模块化方案里需要人工设计 |
| Bounding box（边界框） | 框住物体的矩形，传统感知输出的基本单位 |
| Curse of dimensionality（维度灾难） | 输入维度极大而输出极小，学习正确映射异常困难 |
| Token | 模型处理信息的最小计量单位；这里输入约 20 亿个、输出约 2 个 |
| Transformer | 当代大模型的主流网络结构，靠注意力机制处理长序列 |
| Spurious correlation（虚假相关） | 与真实因果无关的统计巧合，模型泛化差的主因 |
| Data engine（数据引擎） | 从车队海量行驶记录中筛选、定向采集高价值训练数据的系统 |
| Occupancy grid（占用栅格） | 把 3D 空间切成小格子、标注每格是否被物体占用的空间表示 |
| Gaussian splatting（高斯泼溅） | 用数万个带颜色与透明度的椭球重建 3D 场景、可实时渲染的技术 |
| COLMAP | 从多视角照片反推相机位姿的传统工具，splatting 管线常用其做初始化 |
| Nerfstudio | 学界常用的神经渲染工具包，演讲中作为传统 splatting 的代表 |
| Camera baseline（相机基线） | 相机视角之间的差异幅度；车辆直线行驶时基线小，3D 重建难 |
| Open-loop / Closed-loop（开环/闭环） | 开环＝模型输出与既定剧本比对、不回灌；闭环＝输出影响下一帧输入（真驾驶或真模拟） |
| State-action pair（状态-动作对） | 某时刻的环境快照 + 当时执行的动作，驾驶数据里免费存在的监督信号 |
| Action-conditioned（动作条件化） | 生成结果随输入动作变化——同一模型给不同动作生成不同未来 |
| Autoregressive（自回归） | 输出逐段接回输入、滚动生成的方式 |
| Test-time compute（测试时计算量） | 推理阶段愿意花多少算力，多花通常换更高质量的答案 |
| Reasoning tokens（推理 token） | 模型先写显式思考链再给答案时的中间 token |
| System 1 / System 2 | 心理学双系统理论：快速直觉 vs 慢速推理；对应演讲的 fast path / reflective mode |
| Ground truth（真值） | 作为参照标准的事实数据 |
| Closed-loop RL（闭环强化学习） | 让策略在环境里试错、用奖励信号改进的方法；环境由世界模拟器提供 |
| VLA（Vision-Language-Action） | 视觉-语言-动作模型：看图像、懂语言、出动作的统一模型；主办方博客称 Tesla 架构为其变体 |
